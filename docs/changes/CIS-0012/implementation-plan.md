# Bounded follow-up

[Reconciliation](../../../planning/application/follow-up/README.md) fixes the
profile below. Andrew Spiteri approved this profile and the shared allocation on
18 November 2026. CIS recorded the outcome authorization and derived the four
canonical tasks; eligible work proceeds within their finite capacity. CIS-0011
remains closed. No push, merge or release is included.

## Approved delivery profile

- P01: preserve the existing branch/baseline, user launch settings, runtime
  contracts, SDK10.0.401/runtime10.0.12 pins and eight-tutorial consolidation.
- P02: narrow public owner/factory and optional monitored-registration capability;
  keep concrete APIs and IHeartbeatService compatible. Production retains its
  actual internal atomic binder; public manual/recording substitutes use the same
  monitored extension dispatch without internal access.
- P03: alias existing Healthcheck monitor/snapshot interfaces and Heartbeat owner
  factory to the same default state. Respect overrides and borrowed instances;
  document that business replacement is not whole hosted-module replacement.
- P04: guarded public REST terminal-result construction and the existing reusable
  Core DisabledMetrics singleton. All result properties stay immutable, expected
  failure/status rules stay enforced, and runtime exception distinctions remain.
- P05: small optional CIS.CommonTesting package, Core-only approved closure, no
  testing framework/mock/OTel/Polly dependency. Manual Heartbeat, recording health,
  scripted REST, bounded structured logging and one promoted manual clock only.
  Existing repository/process fixtures stay nonpackable. Snapshot stub accepts
  configured genuine snapshots; minimal remaining consumer dependencies use
  public interfaces, without a fake host or policy engine.
- P06: explicit captured per-client LogCalls defaults true; CountryData opts its
  countries profile out of automatic REST call diagnostics. Other clients retain
  their existing automatic logs and every real result/metric/cancellation fact.
- P07: CountryData initial milestones/publication Info once; routine successes
  silent at normal levels. First failure promptly Warning/Error as appropriate;
  thereafter at most one failure summary and one recovery summary per sliding
  one-minute reporting budget, with at least one minute between reports of each
  category. Budgets survive flaps; suppressed counts saturate and are reported.
  Use monotonic time, stable IDs, no message-key dictionary or retained history.
- P08: retain exactly the provider created by the native default factory; transfer
  fallback ownership only when Build returns the host. Await failed-Build cleanup
  and actual module/logging drains; borrowed instances remain borrowed. Preserve
  original startup failure and separate cleanup faults, without a disposal engine.
- P09: focused native and genuine package evidence. No prior Windows result is
  credited to this diff; no broad campaign, new runner or replacement of real
  scheduler/binding/drain proofs with manual doubles.
- P10: requested editorconfig options and concise maintainer rules; format only
  changed files. Correct the guide: initial Configuration load before construction,
  construct-all stage1, then sequential stage2 with activation prepended.

## Acceptance and proportional verification

1. Existing concrete APIs and IHeartbeatService implementers remain usable;
   public manual monitored registration accepts recording monitors through the
   ordinary extension. Preserve real atomic binding/settlement negative cases.
2. Default aliases share state, explicit overrides work at the documented scope,
   borrowed instances are not disposed by alias ownership, and owned aliases do
   not multiply actual cleanup.
3. An assembly outside every friend list consumes real Core/CommonTesting
   packages and the current compiled CountryData assembly. It scripts initial
   JSON, inspects the one-hour schedule, triggers refresh, compares MT/MLT/Malta,
   retains last-good data after failure and closes without HTTP or sleeping.
   The fixture verifies current nupkg/deployed hashes and normal package closure.
4. No routine normal-level success stream at10ms-equivalent intervals. Verify
   first failure, repeated expected/unexpected failures, recovery and flaps across
   59.99/60second boundaries and UTC jumps, suppressed counts, expected shutdown
   neutrality and foreign OCE propagation. Every actual result/health observation
   still occurs. Two real clients prove the scoped REST switch/default and its
   captured immutability; fake REST alone cannot prove this interaction.
5. Web/nonweb lifetime-factory regressions fail after constructing an owned async
   dependency, then prove disposal joins its held cleanup exactly once, keeps an
   external instance undisposed, retains the original startup failure and exposes
   a separate cleanup fault. Preserve graph-validation/successful-host behavior.
6. Existing relevant real Heartbeat, Healthcheck binding, cancellation and actual
   drains remain passing. Targeted formatter verification and documentation links
   pass. No Linux, live provider, performance or release claim without execution.
