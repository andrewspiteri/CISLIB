## Implementation direction and constraints

Use the existing Management PostgreSQL authority, trusted Configuration catalog,
current native Security/Transactions/Operations/Messaging/Audit/Jobs/Coordination
owners and existing provider/process/CommonTesting fixtures. Startup is sequential.
Scheduler event receipts, complete fanout, pending responsibility, worker dispatch,
actual attempt provenance, original-result recovery and durable history are real
production work; screenshots, snapshots or source presence cannot substitute it.
Keep tests, docs, formatting and independent review with coherent medium tasks.
The integrated consumer is one maintained CountryData opt-in plus existing fixtures,
not another framework or broad qualification campaign.

Application Capabilities catalogue registered schedulablejobtypes, actualruleengine
instances and trigger/providerfeatures with trusted versioned definitions separate
from instance support/freshness. Keep protocol API descriptors compatible. Do not
create a rulesengine, new broker/lease/DI/auth/test framework, arbitrary code/form
execution, generalcron/expressionlanguage, unrelated provider, independent worker
fleet or deploymentorchestrator. No newpackages or versionpin/sourceallowlist edits
are planned. No mobile, externaldeployment/liveEntra/AKSqualification,push/merge/release.

Retain R06 shell/applicationlist/instances and accepted task-centrededitor: main
association/resource/inputmapping above exactly Trigger and Job contextual tabs,
History separate. Names/environment/configurations lead; stable rawIDs and copy
controls are under collapsed Technicaldetails. New uncovered visuals require exact
UI previewapproval. Known finite trusted formcontrols are the selected RM10UI04
exception to the old genericserver-drivenUI exclusion; no arbitraryReact/scripts/URLs.

Reuse complete native RM08 source validation/preview/publication/release/whole-map
assignment/promotion/rollback/adoption and original-key recovery. Human actors need
actual scoped write+lookup grants. Values/defaults/history detail permissions remain
separate. Partialcommit/Unknown/cancellation/freshness are explicit; no mutation auto
replay or inferredrollback. Runtime records preserve actual actor, capsule, operation,
lease, workerbuild and attempt identity. Workloadexecution cannot borrow human identity.

All budgets/owners and same physical6GiB/64MiB reserve/max2GiBDocker pool are in the
outcome authorization. Source/reference import and controller task decomposition
are not newhuman numeric/design approvals. Preserve old failures/compensation/costs.
