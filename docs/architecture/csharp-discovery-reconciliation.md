# Native discovery and case reconciliation

WP07-S01-T05 retains the original case IDs and requirement links. Eighteen previously planned unit/integration groups now declare explicit required method bindings selected from the functional, candidate-consumer and concurrency qualifications. A group passes only when every binding is independently discovered and executed. Existing leaf cases retain their own minimum execution counts. The 18 groups contain 200 binding entries over 185 distinct methods; overlapping groups are not additional tests. Precedence binds the 26-row configuration table and explicit layer/alias controls; bounds binds numeric, cross-option and invalid-input controls. For groups, bindings supply the authoritative methods/minimums; retained root method:null/minimum fields are original metadata. Nine architecture, mutation and cumulative compatibility/business obligations remain Planned; no publication history is invented.

The nonshipping CIS.Discovery.TestLogger uses the pinned SDK's existing Microsoft test-platform ObjectModel assembly. It adds no NuGet or Core runtime dependency. VSTest discovery events produce a fresh discovery-native.json containing each DataRow's native ID, fully qualified method, display name and source assembly path, plus total/abort/error facts. Console short names are not identities. VSTest's fully-qualified listing also removes DataRows, so it cannot replace this native event evidence.

The verifier checks the independent discovery record against TRX execution by exact native ID, method, display name and normalized source path. For display names alone it also accepts the pinned older TRX writer's one-way encoding of UTF-16 surrogate and XML-invalid code units as literal lowercase backslash-u sequences. ISO-date-like names are parsed as strings and method/name equality is ordinal. Well-formed Unicode names remain unchanged; lone-surrogate display names are unsupported and fail closed after the JSON encoder replaces invalid UTF-16. No lossless lone-surrogate discovery claim is made; literal backslashes are never decoded. Unicode-modern/legacy positives and literal/swapped-escape negatives qualify this narrow presentation comparison. IDs, methods and source paths are never normalized this way. Aborted/error/empty discovery, duplicate or missing IDs, class/name/source mismatches, incorrect totals, missing required methods, failed tests and unexpected skips fail verification. Duplicate case IDs, unknown case lanes and empty/ambiguous/duplicate group bindings also fail. Executing Developer with a lane that differs from the actual OS/architecture fails before running tests. Fixture data sources select their explicitly applicable platform rows; platform selection is not an unexpected skip.

Each run deletes an older discovery-reconciliation.json at startup, then produces a new report in finally when its six-family inventory exists. The summary explicitly records Produced with a hashed report reference or NotProduced with its reason. The report carries the same run ID and source commit/input-inventory reference as the summary. The standalone checker validates the declared report hash and run/source/profile/lane identity when families executed. Older foundation reports with neither a run ID nor this supplementary field retain their original format. Removing the reconciliation from a current run is rejected. Skipped rows remain reported with skipped counts and are excluded from executed counts. It includes every applicable or inapplicable case, every required method/minimum and its discovered/executed/passed/failed/skipped counts, genuine pending work and the union of discovered/executed supporting methods. Methods bound only to inapplicable cases are classified separately from unbound technical methods. Group and leaf bindings may share executions. Native row totals count each ID once; adding group counts is not a test total. Supporting technical passes are recorded without inventing a business requirement. Mutation and cumulative compatibility remain separate pending families. Method-row counts apply to VSTest reports; the declared mutation format is preserved without pretending mutant counts are test methods.

Both initial release lanes remain required. Current Windows and Ubuntu executions, source manifests, native reports, loaded candidate identities and any platform limitations are recorded in the [task evidence](../../planning/logging/evidence/wp07-s01-t05/verification.json). The three Type Manager test/example hosts now declare the already-supported win-x64 and linux-x64 RuntimeIdentifiers, and their generated lockfiles retain both targets. This fixes native locked restore without changing the selected RuntimeIdentifier or Type Manager implementation. NuGet source mapping also names the six SDK framework/runtime-host download identities at the existing target runtime version; a fresh native cache cannot borrow these from an installed Windows cache. These SDK downloads do not add Core PackageReferences or bundled runtime dependencies.

An isolated verification copy avoids locked shared obj files; canonical edits remain in the main checkout. It includes maintained code/contracts/conformance/docs and the one retained checker fixture, with a recorded input snapshot commit. Unrelated historical reports and the other chat's untracked launch profile are omitted from that test copy. This is a current test run, not an offline release kit or publication.

The native checker controls use a copied genuinely executed historical TRX as data, with source locators relocated for the host OS. Its discovery fixture is derived checker input, not current independent discovery or historical compatibility evidence. Actual suite runs use the live discovery logger and separate execution. Positive leaf/group controls and negative identity, missing-row, duplicate-ID, count, lane and binding controls qualify the checker.

Microsoft documents the [discovery logger events](https://github.com/microsoft/vstest/blob/main/src/Microsoft.TestPlatform.ObjectModel/Logger/TestLoggerEvents.cs) and the [fully-qualified listing's DataRow deduplication](https://github.com/microsoft/vstest/blob/main/src/vstest.console/Processors/ListFullyQualifiedTestsArgumentProcessor.cs). The committed source and retained native reports establish the behavior actually used here.

Verification requires PowerShell 7.5 or later for string-preserving JSON parsing; these native lanes use 7.6.5. The scripts declare the minimum before execution.

Each native test family has a five-minute VSTest session deadline. The previous two-minute guard aborted Ubuntu after 520 passing architecture rows with three rows still undiscovered in execution; that incomplete attempt was rejected, not accepted as a pass. This timeout is a harness bound, separate from each behavior test's own deadlines.

The Developer runner uses explicit four-worker MethodLevel MSTest settings for both discovery and execution. The prior processor-count default selected 20 workers per native process; simultaneous native suites exceeded unchanged child-process deadlines. Worker selection limits harness contention without changing individual behavior-test deadlines or expected outcomes. The shared runsettings file owns the five-minute family deadline.
