# C# ownership and output boundaries

WP07-S02-T03 adds C# guards to the existing Developer architecture inspection. The checker still inventories every project/target and both package assemblies independently. Its additional `cis.architecture-ownership/v1` observation reports checked immutable types, contract use sites, approved setup exceptions and exact package entries. It writes a successful inspection only after all dependency, ownership and package checks pass.

The user-selected static `EnvironmentOptions` constructor remains authoritative: automatic facts are readonly, defaults precede known environment overrides, and the four bounded common identity strings are interned. `EnvironmentKind`, `CommitId` and `BuildId` remain ordinary mutable setup properties. The getter-only `Logging` reference contains mutable module settings. Configure those inputs before creating a runtime; concurrent setup mutation is unsupported. Readonly environment properties require matching static readonly backing fields; nested container state is rejected for the current pinned implementation. This task does not restore the superseded publication/snapshot framework.

The guard inspects compiled fields, setter signatures and property return types for the actual captured metadata, values, event/scope/exception payloads, public observations/results and readonly transport/accounting values. Newly discovered capture and logging result/diagnostic/snapshot shapes join the check automatically; the current required roots must also remain present. Fields must be readonly or literal and contain selected scalar/enum values, checked immutable Core values or read-only collection views of those values. Writable collection types, arbitrary caller-object types and mutable module settings cannot be declared field types in those values. Read-only interfaces and collection views can still alias a caller collection; only the executed ownership tests establish copying. Reference types must be sealed, derive directly from System.Object and have no setters. The readonly record structs retain their compiler-generated init accessors.

There are two narrow byte ownership rules: the internal encoder transfers its newly allocated private byte array into `EncodedEvent`, and the admitted-event transport carries internally prepared bytes through a readonly memory view. These are inspected shapes, not a proof against hostile reflection or `MemoryMarshal`. Runtime, logger, provider and output component fields, including nested types, additionally cannot retain `LoggingOptions`, `LogEventData` or `OperationContextData`, including inside a collection signature. Runtime lifecycle and synchronization state remain mutable as required by the implemented pipeline.

Environment/configuration, text helpers, event/value/exception/scope capture, renderers and immutable contracts cannot depend on output implementations or provider orchestration. The check uses actual signature/IL type-use sites. `LogOutputDiagnostics` legitimately consumes the readonly `OutputAccounting` value; the same immutable field checks cover this value. This is not permission to reference queues, writers, runtime orchestration or the Microsoft provider from contracts. The runtime and provider remain the composition layer.

The corrective incoming pipeline adds `IncomingAccounting` to these required immutable values. `LogIncomingSnapshot` copies its scalar counters. The checker validates its readonly field closure; negative controls reject a writable counter or retained writer. Queue and worker dependencies remain prohibited for snapshots.

Every entry in the actual ZIP is inspected, including content outside `lib/`. The package hash, entry inventory, sizes and bytes must agree with the inspection. Only Core DLL/XML, the built XML documentation, source README, NuGet-generated metadata and the already approved Type Manager helper/SDK/build assets are permitted. The five maintained build assets must equal their source bytes; the generated version props must contain only the selected package-version property matching the nuspec. Type Manager implementation is unchanged. Unexpected content, test binaries, extra scripts, missing/duplicate paths or modified approved scripts fail with a specific `ARCH-PACKAGE-*` diagnostic. Packed DLL hashes must also match their inspected and built assembly facts. The earlier independent DLL origin/hash and dependency checks remain required.

Readonly fields and `IReadOnlyList` cannot establish that constructors copied a caller collection. Executed behavior remains essential:

| Ownership requirement | Existing executed Core coverage |
| --- | --- |
| Automatic readonly facts, ordinary setup values and interned identities | `EnvironmentConstructorTests` |
| Runtime and physical-output choices remain frozen after setup changes | `LoggerFoundationTests`, `ConsoleCompositionTests`, file/timer composition cases |
| Nested collection copying and readonly returned views | `LogValueTests.OwnedNestedCollectionsSurviveEveryCallerMutationAndRemainReadOnly` |
| Captured DTO, dictionary wrapper, exception and scope independence | `EventProjectionTests.CapturedFactsSurviveDtoDictionaryExceptionAndScopeReplacement`; `EventFactsDoNotRetainStartupInputsConfigurationCallerExceptionOrScopeStore` |
| Configuration issue collection ownership | `ConfigurationDiagnosticTests.ExceptionCopiesAndEnumeratesIssueInputOnceInOrder` |
| Diagnostic, flush and stop observations stay frozen through later work | `DiagnosticsTests`, flush coordination/results and stop/deadline tests |

Forty-two new C# architecture executions comprise one real native positive, twenty-six isolated compiled-fact violations, and fifteen controls over actual copied package bytes or their observed facts. Every negative first passes the unchanged positive. This qualifies the new policy paths; [compiled source/package/binary fixtures](csharp-architecture-violations.md) for the material checker levels are added in WP07-S02-T04. Static metadata does not infer reflection strings, serialized attribute arguments or dynamically selected dependencies. This task does not qualify release coverage, mutation, cumulative compatibility or offline replay.
