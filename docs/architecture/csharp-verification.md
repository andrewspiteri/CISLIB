# C# verification and source replay

Run the repository-owned commands from a Git worktree at the intended revision, with PowerShell **7.5 or later**, Git and .NET SDK **10.0.401** on PATH. The architecture inspector reads the real Git HEAD; a directory-only source archive must first acquire matching Git metadata and pass source-integrity checks. Developer restore uses the explicitly mapped NuGet source. The selected target runtime is **10.0.12**. Separate mutation/API tool qualification also requires **8.0.31**; see [toolchain qualification](csharp-toolchain.md).

For native Ubuntu runs, place the checkout, SDK and PowerShell on the Linux filesystem and verify the selected versions before starting. Repeated tool launches from a Windows-mounted SDK exceeded the unchanged architecture-family budget in the [16 October qualification attempt](../../planning/evidence/corrective-qualification-2026-10-16/README.md); the byte-identical native-filesystem copy removes that overhead.

```powershell
pwsh -NoProfile -File eng/verify.ps1 -Profile Developer
pwsh -NoProfile -File eng/check-release.ps1 -Profile Developer
pwsh -NoProfile -File eng/verify.ps1 -Profile Release
pwsh -NoProfile -File eng/check-release.ps1
pwsh -NoProfile -File eng/replay.ps1 -Profile Developer
```

Developer verification performs locked restore, evaluated dependency checks, format validation, Release build, Core packaging, compiled/packed dependency checks, actual discovery and execution of unit, integration, architecture and business projects, compile-only startup specification/consumer controls, publication-ledger validation, and host execution. Stage exit codes, timestamps, source hashes, native reports and validation issues are retained. Exit **0** means the selected foundation checks passed; **1** means an execution stage failed; **2** means evidence validation refused the selected profile. Check-release returns 0 for accepted evidence and 2 for refused or malformed evidence. Replay propagates verification's exit code, or returns 1 for materialization/checksum failure.

Reports use stable paths under `.artifacts/csharp/verification/<Profile>/`: `summary.json`, `source-inputs.json`, `validation.json`, stage `logs/`, and independent `families/<id>/discovery.json`, `execution.json` and native report slots. A new invocation replaces its structured slots and selected native reports; retain any run needed as evidence before running again. Unexecuted families explicitly record `NotRun`, with no native-report reference or pass claim. Legacy populated-family TRX copies remain under `.artifacts/csharp/tests/` for the separate toolchain qualification command.

Source inventory is implemented in the C# checker (`source-inventory <root>`). The PowerShell bridge builds that tool with locked restore before capturing inputs, so a fresh checkout needs no prebuilt checker and build messages cannot contaminate its JSON. An empty Git repository-relative prefix identifies the root even through a directory alias. At that root, it reads tracked and nonignored untracked paths, excludes Git-confirmed working-tree deletions, and hashes current file bytes without changing the index. Null-delimited Git output preserves filenames containing spaces or non-ASCII characters. An invalid repository/index fails instead of producing a partial inventory. A directory outside its own Git root uses copy enumeration, including hidden source files but excluding `.git`, `.artifacts`, `bin`, `obj` and `.vs` directories and not traversing directory links. Paths are unique, use `/`, and sort ordinally; hashes remain lowercase SHA-256. This copy branch does not meet the full profile's Git HEAD prerequisite. Native SourceInventoryTests cover both branches, owned Windows junction/Ubuntu symbolic aliases, unchanged index bytes, current digests, rejected corrupt indexes, command JSON/error output and a fresh tool bootstrap.

[The family manifest](../../implementations/csharp/verification/families.json) declares unit, integration, mutation, architecture, compatibility and business families, with Windows x64 and Ubuntu 24.04 x64 applicability. Mutation remains a separate development CLI rather than a sixth C# test project. Its parser qualification is an explicit separate command, not part of fast Developer verification. Native Ubuntu execution uses Ubuntu 24.04 WSL2 and requires PowerShell on PATH for child checks. Current lane results and outstanding qualification are recorded in the [feature report](../../planning/feature-status-2026-10-15.md). The [case inventory](../../conformance/logging/case-inventory.json) distinguishes implemented native-method bindings from required planned case groups; the [requirement map](../../conformance/logging/requirement-case-map.json) preserves acceptance obligations and the user's amendments. A mapping or method binding is not passing evidence. Extend planned groups with concrete case IDs as behavior is implemented.

Release-evidence policy is implemented in the existing C# checker (`VerificationEvidence.cs`, command `release-evidence`). The stable PowerShell launchers and `Evidence.psm1` retain bootstrap, process invocation, JSON output and reference/copy glue. Family discovery wrappers, TRX/discovery parsing, required case/group minima, counter and identity checks, six-family validation, and reconciliation now use the same C# implementation. The two isolated Type Manager harnesses copy and hash the managed reader and its runtime files alongside the module; they do not depend on the source checkout after copying.

The validator verifies referenced report hashes and confined paths, native TRX schema/definitions/counters, populated independent discovery, exact method/name/source identities, required case counts, failures and skips. Current reconciliation requires matching declared run/source/profile/lane identity; historical foundation reports without reconciliation retain their original treatment. Known legacy UTF-16 TRX display-name escaping and historical integral decimal counts remain supported; fractional counts are refused. Native paths follow the host's case rules.

`VerificationEvidenceTests` retains the original 55 controls and adds 22 migration controls, including stable launcher acceptance/refusal and a source-independent copied reader. Shared checker bootstrap cases run serially. The case inventory explicitly binds discovery, identity, reconciliation and migration controls. Altered copies test the validator; they never qualify a candidate package. Pending release gates and planned cases still refuse Release validation, and a mutation slice cannot satisfy the full shipping mutation gate.

Release verification currently inventories missing work and returns nonzero. Complete candidate qualification, coverage/mutation validation, compatibility history, package-consuming teaching examples, both-lane release gates and the retained offline verification kit remain open. Bootstrap commands cannot certify a release, and parser-only mutation evidence cannot satisfy the full shipping mutation gate.

## Source replay

Replay defaults to the Release profile, which currently fails as expected. The current Developer replay materializes content without Git metadata, so its full architecture-inspection stage cannot qualify that directory. Restoring pinned source/Git provenance is remaining replay work; source-inventory fallback alone does not supply it. Each replay retains a unique directory under `.artifacts/csharp/replay/<UTC>-<id>/` and a stable `latest.json` pointer containing the result. It copies maintained inputs into separate `input/` and `work/` directories, creates fresh CLI-home/NuGet/HTTP caches, runs verification in `work/`, and checks hashes of caller inputs, retained inputs and working sources before and after execution. Reports and generated build outputs stay outside the input inventory. Repository discovery cannot borrow the enclosing checkout's Git identity.

Optional `-InputRoot` and `-InventoryPath` accept another source directory and a JSON array of `{ "path": "relative/path", "sha256": "lowercase SHA-256" }` entries. An inventory is nonempty, and every path must stay inside its input root. An input checksum mismatch refuses execution. Fresh-cache replay checks source reproducibility within the installed pinned SDK/runtime environment; unchanged historical binaries, exact candidate package consumers, offline prerequisite restoration and historical runtime replay are not yet implemented.
