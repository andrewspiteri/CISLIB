# Microsoft provider scope capture

CoreLoggerProvider implements ISupportExternalScope in the existing CIS.Core assembly. SetScopeProvider borrows an IExternalScopeProvider; it never pushes or disposes host handles. These owned-scope rules describe direct CreateLogger calls; [host qualification](microsoft-host-qualification.md) covers actual LoggerFactory-driven routing. Replacing that source applies to later calls. Each Log call freezes one source reference, so an in-flight call can finish using its original source. Registration and provider disposal share a small lock; callbacks run outside it. Null registration throws ArgumentNullException before the disposed guard. Registration after provider disposal throws ObjectDisposedException. Disposal releases the source reference and leaves runtime and host scope lifetime with their owners.

The provider's own BeginScope keeps Core's existing runtime-owned AsyncLocal store. It accepts OperationContextData or IEnumerable<KeyValuePair<string, object?>> state, including Microsoft's formatted BeginScope extension state. It copies at scope creation before returning the handle. Typed operation IDs retain Core validation/trim rules. Structured scopes use the existing scalar/nested collection allowlist and bounded value copier without the event_id reservation. The exact OriginalFormat metadata is excluded; no scope message parser or arbitrary ToString fallback is added. Bare strings and unsupported objects are rejected. The exact structured operation_id key maps CLR string values into typed identity; [operation mapping](microsoft-provider-operation.md) specifies blank, duplicate, non-string and bounded behavior.

Owned scope handles retain Core's creator-disposes rule, depth 32, LIFO errors and repeated valid disposal. Scope capture preserves the existing reentrancy guard. A closed runtime rejects creation before content copying. Provider disposal does not pop caller-owned handles; their creator still disposes them. Existing .NET inherited-child-flow detection limits remain documented in [operation scopes](operation-scopes.md).

Host scopes are copied synchronously only for an event passing Core's closure/interest/fault gates. The IExternalScopeProvider contract invokes callbacks inline in creation order. The adapter accepts the same typed/structured state and constructs at most the remaining number of immutable Core frames. Mutable host state is observed at Log time, not at host Push time; later mutations cannot change queued facts. Invalid borrowed scope state rejects the event and increments InvalidEventCount once, without admission or truncation classification. Unsupported roots/values, malformed Unicode, invalid operation IDs, cycles, non-finite values, external-provider errors and excess combined depth follow this rule. Valid oversized state still truncates. Bare strings are unsupported through both owned and borrowed routes. The formatter still runs before scope capture and retains its existing exception behavior. Activity IDs and the event clock are frozen before host callbacks, protecting correlation from ambient changes inside those callbacks.

The two stores have a defined layer order: captured Core/provider-created scopes first, borrowed host scopes second, event attributes last for matching retained keys. Event attributes have priority over remaining scope keys under the aggregate budget. Within each store later scopes win. A nonblank typed host OperationId replaces the captured Core OperationId. Direct Core logging consumes only its own runtime scopes. The stores do not provide a combined chronological stack across arbitrary interleaving; factory/external host scopes stay in the host's own creation order. The operation mapping guidance qualifies recognized operation_id and this bounded precedence.

Each scope uses the existing 1024-node/depth-8 projection and truncation provenance; combined Core plus host scope depth cannot exceed 32. Excess host frame depth invalidates the event. Ordinary aggregate/entry truncation can omit attributes. The provider numeric event_id is reserved through node and byte projection, including zero/negative IDs; event keys precede remaining scope keys. Caller enumerators and the borrowed provider remain cooperative code: the adapter bounds copied frames/value traversal, not the execution time or internal traversal of arbitrary provider callbacks. Logging recursively from scope enumeration is unsupported.

Thirteen fixture modes and lifecycle guards cover owned copies, host copy timing, both layer sources, real Microsoft formatted scope state, two coordinated asynchronous flows for each source, node/depth/combined-frame bounds, invalid owned scopes, rejected incompatible host scopes (bare string, Dictionary<string,string> and a real Microsoft HttpMethod value carried by LoggerExternalScopeProvider), filtered traversal, Activity mutation and source replacement/nonownership. Process variants use public runtime creation and real JSONL bytes with post-stop exclusive lease probes. Independent native readers bind PID, exact assemblies, records and fixed-reason corruption controls. Execution and review results belong in the task receipt. No new package, worker or public placeholder is introduced; SetScopeProvider is the previously planned interface method.
