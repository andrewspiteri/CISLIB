WP05-S03-T03 implements the selected four output states in the actual internal Core/Channel worker composition. `LogOutputState` retains Running=0, Faulted=1, Stopping=2 and Stopped=3. Public `GetDiagnostics` follows in T04; physical destination creation, flush coordination and bounded shutdown remain later tasks.

A new output starts Running. Primitive `Complete` closes admission and changes it to Stopping while its worker resolves accepted work; worker completion changes it to Stopped. Empty and successful queues finish without a fault. Repeated closure is harmless.

Terminal callback failure publishes admission closure, one in-flight Failed disposition, all unstarted queued Abandoned dispositions, and a safe last fault code/time together under the existing shared gate. An output whose runtime remains open is Faulted from fault publication, including while an exhausted output still has unresolved in-flight work. Explicit closure moves a finished faulted output to Stopped; fault during an already requested stop finishes Stopped. The independent other worker continues admitting and delivering, including after one output faults. No write is retried and an emitted prefix never confirms a complete record.

`WriteFailed` is the fixed category for any throwing trusted write callback, including synchronous exceptions and terminal cancellation. It never incorporates exception message, type name, stack, payload or path and does not format/log the exception. Internal Completion preserves the original exception object for supervision. `LastFaultAtUtc` uses the system UTC clock at fault publication, with zero offset; it is an observation time, not a deadline. Code and time remain stored after stop. An older owned observation remains unchanged.

Representational admission exhaustion has the internal safe category `AdmissionExhausted`. It closes admission and immediately abandons unstarted queued work while retaining unresolved in-flight work as Pending. That callback may later succeed or fail; a later actual write failure replaces the last fault with `WriteFailed`. Fault disposition and stop state are separate: the internal admission seam retains its historical Faulted response after a fault, while the runtime's closed-admission check returns Stopped for all enabled outputs after runtime closure. There is no recovery or reset.
