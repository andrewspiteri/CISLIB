# Captured variables and source precedence

WP03-S02-T01 implements [recognized-variable capture](../../../implementations/csharp/src/CIS.Core/Environment/Resolution/CapturedEnvironment.cs) and [source selection](../../../implementations/csharp/src/CIS.Core/Environment/Resolution/ConfigurationValueSelector.cs), using Core's internal `CIS.Configuration` namespace. The [catalog](../../../contracts/logging/v1/configuration.json) remains the authority for 18 CORE settings, three DD aliases and their later parsing/default rules. Tests compare the compiled registry against it. No public startup placeholder is introduced.

Each capture reads the exact uppercase 18 CORE names and `DD_SERVICE`, `DD_ENV`, `DD_VERSION` once, including recognized values that may later be shadowed. It never enumerates process variables or reads unknown names, `DD_AGENT_HOST`, framework environment settings or credentials. An ordinal frozen dictionary owns the resulting strings and nulls; it retains neither the source nor a global cache. Reusing it across settings and service-version selection performs no additional process reads. A new resolution takes a new capture. These are sequential reads, not an atomic operating-system environment transaction; changing process variables during capture is outside the stability guarantee.

The shared selector chooses a nonblank CORE token, its one supported nonblank DD alias, explicit setup, discovered value, then a provided documented default. All absent sources produce an explicit absent result. Surrounding whitespace is trimmed, while identity/token case is preserved for the later parser. Selected environment tokens remain strings; typed setup/discovery/default candidates preserve their domains, including zero, long values and undefined enum values. Invalid nonblank higher-priority inputs remain selected with their source; selection never falls through because a token or typed value needs validation.

Source provenance distinguishes environment, setup, discovery and default. Environment selection names the exact CORE/DD key; setup names its predefined input property; service-version discovery names `BuildVersion`. A selection exposes either a raw token or a typed value, with safe errors for reading an absent/untypeable value. Plain classes avoid automatically formatting raw configuration values into diagnostics. Capture/access/programming failures propagate; capture does not return a partial result or silently substitute lower-priority data. These are internal mechanisms; aggregated safe validation errors are WP03-S03 work.

[ApplicationVersionSelector](../../../implementations/csharp/src/CIS.Core/Environment/Resolution/ApplicationVersionSelector.cs) now reuses this precedence implementation, keeping actual BuildVersion separate. Its standalone two-key helper can still use an explicit source directly. Full resolution captures once, then passes the snapshot to this helper and every other setting selector. The [discovery host](../../../implementations/csharp/tests/fixtures/DiscoveryHost/Program.cs) exercises that composition on Windows and Ubuntu 24.04 WSL2.

Forty-seven native cases cover the complete recognized-name/order boundary, registry/catalog parity, owned values and new captures, required read failures, all 18 CORE selections, three aliases, every precedence layer, blank/selected-invalid behavior, typed values, unknown-name rejection and safe formatting. Existing 20 version cases and seven process integration cases continue to execute.
