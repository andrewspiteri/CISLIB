# File timer and flush coordination

WP05-S09-T02 qualifies periodic file requests through the actual Core queue and public FlushAsync callers. Every callback registers a fixed accepted boundary synchronously; it performs no I/O and starts no task. The existing single worker awaits each write and flush, ordering each registered boundary before later records.

Two controlled scenarios hold either the first write or first flush while the three event slots fill. Four accepted boundaries retain four controls, including the active flush boundary in blocked-flush; all four controls remain pending in blocked-write. Another 3,000 timer dispatches preserve all four original registration identities and create no timers. The initial four ticks have observable Core registration effects; idempotent coalescing for the repeated same target is also source-inspected, since an ignored duplicate tick would have the same external result. Five hundred real caller waits cancel with their original token while one surviving caller remains attached. Controls, pending slots and continuation storage stay bounded; after release, actual output alternates each record with its registered flush. The incoming overflow rejection remains visible in the final result without preventing successful accepted-record flushing.

A continuous-traffic scenario writes 128 actual events, advances controlled time and attaches a public explicit caller to each timer-created registration. Exact reference identity confirms coalescing. Each flush completes before the next step; record and writer order are inspected. This is controlled functional qualification, not a filesystem throughput benchmark.

Internal startup qualification verifies that a duplicate start disposes only the extra timer, a start after terminal closure cannot arm work, and an owned timer returning false or throwing ObjectDisposedException from Change still fails and cleans up. A barrier holds Change while the actual worker closes and detaches/disposes the timer. Resuming that initial arm returns harmlessly when Change returns false after the timer is no longer owned. This qualification includes a controlled clock and a wrapped actual .NET 10.0.12 TimeProvider.System timer. The real system probe requires a false return after disposal; timer exceptions remain initialization failures. The boolean result follows the documented [ITimer.Change contract](https://learn.microsoft.com/en-us/dotnet/api/system.threading.itimer.change?view=net-10.0). Configured composition arms once before its runtime is published; these primitive races do not introduce a public initialization API.

The new fixtures use actual Core queues with controlled MemoryStream writer callbacks and a nonshipping periodic/deadline clock. They do not simulate the logging engine or claim active-clock-callback joining, OS I/O cancellation or public bounded shutdown. Physical configured-file and other flush regressions are required separately against the same final assembly; task completion is recorded by the retained evidence receipt. Private field and Task continuation probes are nonshipping .NET 10.0.12 evidence, not public or future-language API promises. Blocked, duplicate-start and continuous tests hold the queue gate as a test barrier while advancing controlled time, so callbacks re-enter it on the test thread; production callbacks acquire it independently. The continuous barrier also encloses controlled caller-clock creation; production does not perform that nesting. Immediate timer cancellation, timer flush failure/isolation and shared stop remain T03; complete S09 acceptance remains T04.

The shared case map is conformance/logging/file-timer-coordination-cases.json. The C# matcher checks principal observations, and the independent native reader checks queue/control/timer accounting, original PID and UTF-8 records, cancellation/storage counts, actual result boundaries and writer order. Thirty exact-reason corruption controls exercise these checks. All original source files, earlier task receipts and the 41 Planned release rows remain unchanged.
