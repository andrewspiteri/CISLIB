# Explicit presentation (WP05-S01-T03)

`EventRenderer.Render` is an internal selector with four arguments: owned `EncodedEvent`, explicit `LogOutputFormat`, `HumanOutputDetail` and maximum entry bytes. JSONL returns the original readonly memory and capture-loss flag. Human calls the real bounded human renderer and returns its owned memory and combined capture/display-loss flag. The result is an internal readonly value containing only memory and loss state. No caller graph, output settings or destination object is retained.

Filtering and destination selection stay in the runtime/output composition layer. The selector receives no severity threshold, logger/runtime, settings store, path, console stream, terminal or debugger state. Its rendering code calls no routing, configuration, ambient clock/scope/activity or terminal/debugger APIs. Invalid enum choices fail explicitly; they do not fall back to an inferred format. Runtime composition uses one prepared cap for capture and outputs. The selector checks actual JSONL bytes rather than rebuilding the schema; a selected cap below the captured JSONL length is an internal composition error. A valid different cap that still fits the captured bytes is accepted. Human applies its own escaped-byte budget through the existing renderer. Normal/verbose are presentation choices, not levels.

Messages and supplied templates remain literal captured strings. Braces, format-looking text and missing placeholders are neither parsed nor expanded, even when matching attribute keys exist. The future Microsoft provider uses its supplied formatter; this selector adds no template language.

[Shared cases](../../../conformance/logging/presentation-cases.json) contain four profiles (console Warning/file Debug with fallback Information, console only, file only and both disabled), crossed with both console/file formats, both human details and both explicit streams. All seven level values run against the real logger and explicit non-I/O admission controls. Literal outcomes, accepted-only tickets, factory/clock counts and enabled states do not change with presentation. Both a unit control and the independent native comparator require identical expected admission blocks across all sixteen presentation choices within each profile. The explicitly overridden both-output thresholds qualify that fallback Information is not a global upper bound; they do not exercise threshold inheritance. The disabled profile qualifies zero capture/admission rather than rendering. The admitted owned records render after caller values and ambient context change; original bytes and the captured UTC/correlation/operation facts remain intact. JSONL storage is reused and human detail expands only the promised information. Test rendering arguments come directly from each case; this is not a claim that runtime format/destination composition already exists.

Fresh process checks observe redirected stdout/stderr and no attached debugger, with `TERM=dumb`, `NO_COLOR=1` and a poisoned unused environment level. The independent native comparator checks the original bytes and captured meaning. A shipping-IL boundary check inspects every rendering method/constructor for forbidden direct dependencies; real forbidden call sites qualify the inspector. This does not execute an attached debugger or interactive TTY, prove arbitrary reflective/transitive behavior, or promise a permanent ban on a future explicitly configured color feature. Canonical source inspection confirms the current implementation uses neither inference nor reflection.
