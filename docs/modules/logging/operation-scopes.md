# Operation scope foundation

WP04-S03-T01 implements the caller-owned `CIS.Logging.OperationContextData` input and internal `CIS.Logging.Scopes.OperationScopeStore`. A future CoreLogRuntime owns one store; actual runtime construction, admission/closure and its public BeginScope method remain later integration work. This helper creates real scopes without starting logging or reading startup configuration.

The input exposes nullable OperationId and IReadOnlyDictionary<string, LogValue> Attributes, matching the preserved reference surface. BeginScope reads the input properties once, trims the optional identifier, treats blank as absent and rejects retained malformed/control text or more than 255 Unicode scalars. Identifiers are correlation values and are never silently clipped. Null attributes become an empty map. LogValue.Map copies the caller dictionary, uses ordinal keys and applies the existing root-inclusive 1024-node/depth-8 projection. Immutable LogValue children may be shared; caller maps, DTOs and mutable source arrays are not retained. Existing and newly observed truncation remain on the captured map for later merged/event capture.

Each store has its own AsyncLocal slot. The slot points to an immutable frame with copied payload, immutable parent link and cached depth. BeginScope replaces the current flow's head; it does not mutate an inherited frame or a shared environment identity. Child tasks inherit normal execution context; their own pushes/pops leave the parent and sibling heads unchanged. Suppressing execution-context flow suppresses inheritance. [Microsoft's AsyncLocal documentation](https://learn.microsoft.com/dotnet/api/system.threading.asynclocal-1) describes context propagation, and [the CLR implementation](https://source.dot.net/System.Private.CoreLib/src/runtime/src/libraries/System.Private.CoreLib/src/System/Threading/ExecutionContext.cs.html) shows immutable execution-context capture and replacement.

The initial helper enforces depth 32 before traversing content, captures before publishing, allocates the handle before changing the head and rejects a stale parent if a cooperative map enumerator re-enters scope creation. Input callback cost, failures and deliberate callback side effects are caller behavior, as with existing value factories. A failed outer capture does not overwrite a newer head.

Normal LIFO disposal restores the prior head; initial guards reject an ancestor's out-of-order disposal without mutation and permit repeated disposal after a completed pop. Handles must stay in their creating logical flow and must not be passed to another concurrent flow. Full disposal/ownership qualification remains T03. In particular, an inherited head has the same frame reference in parent and child contexts: head identity alone cannot prove the owner. T01 does not claim the reference runtime contract's universal cross-flow rejection; resolving that stronger guard before runtime publication remains explicit T03 work. The original reference contracts are preserved, not silently weakened.

Native foundation cases exercise identifier normalization/scalar limits, malformed native code units built inside test bodies, copied DTO/map/nested inputs, all eleven value kinds, root budgets and truncation provenance, real await/task inheritance, two barrier-controlled operations/two independent stores and normal disposal. T02 completes outer-to-inner merge and bound qualification; T03 completes disposal/ownership; T04 completes the shared scope scenarios and full story qualification. Event encoded bytes, activity capture, runtime/logger integration and release remain later work.
