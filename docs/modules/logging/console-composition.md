The internal CoreLogRuntime.CreateConsoleQueued path captures the effective levels, file enablement, queue capacity, entry cap, console format, human detail and selected stream before invoking a stream selector or starting workers. It copies the module options once, rather than adding another public environment snapshot. Configure options before creation; concurrent caller mutation during capture is not an atomic-snapshot promise. Mutation afterward, including from the selector, cannot change the selected behavior. The existing callback-based CreateQueued path retains its earlier unformatted controlled-writer behavior.

An enabled console uses the existing independent bounded worker. StandardError selects Console.OpenStandardError; StandardOutput selects Console.OpenStandardOutput. Disabled console output never selects a stream or creates a console worker. Human/Normal and stderr remain the module defaults; JSONL on the default stream also goes to stderr. No terminal, debugger or output-redirection inference changes presentation. Application stdout can remain a command-result stream while console records use stderr. T01 includes initial exact-runtime physical-stream consumers, while complete environment-driven consumer/ownership/startup qualification remains T02-T04.

The runtime captures one immutable JSONL event, then prepares the interested healthy console representation outside the admission gate and before queue admission. JSONL reuses its original readonly bytes; human uses the existing bounded renderer. The queue slot retains the original event and optional owned prepared memory, with its successful ticket. The console worker only writes that memory and never recaptures, guesses a format or retains caller options/context. Controlled file callbacks continue to receive the original JSONL object without console display bytes. This prepares the real console output; physical file composition remains WP05-S05.

LogWriteResult.IsTruncated and global TruncatedEventCount combine capture loss with additional interested console display loss, counted once per valid event before admission. Capture and human loss together still count once. The original JSONL capture flag/bytes are unchanged, so a human-only omission does not rewrite the file event. An uninterested or already faulted console does not add new display loss. If the console faults after the initial healthy-interest check, the prepared loss still counts even if that output later rejects admission. A later closure or queue-full rejection can still return truthful loss from the event already prepared. The existing protected-envelope validation/error rule applies to rendering as well: an unrepresentable human protected envelope makes the whole event Invalid before any destination admission, including a file that could otherwise accept JSONL. Ordinary oversized payload is truncated under the user-selected policy, with actual escaped bytes and LF within the selected cap. Filtering/early rejected calls still skip factories, clock and capture.
