> Historical implementation/evidence: the passive caller-populated store in [current guidance](environment-options.md) supersedes these discovery/factory/publication tasks. Original receipts and source proposals remain preserved; do not recreate the removed startup subsystem from this walkthrough.

WP03-S02-T04 supplies the [language-neutral configuration table](../../../conformance/logging/configuration-resolution-cases.json). Its 26 independently declared rows cover every default, complete typed setup, all CORE overrides, the three DD aliases and their precedence, blank fallbacks, independent/inherited thresholds, None/absent-path disablement, explicit formats/stream, Unicode/case, selected-invalid values and differing host/telemetry labels. Each expected snapshot declares all 18 settings in catalog order, with parsed value/state, source/key, inherited threshold source, output enablement and actual BuildVersion.

The table describes parsed selection before option ranges, identity/path validation or public startup. Formats, stream and detail use portable tokens; severity uses canonical names, numeric settings retain integer domains, and setup uses flattened catalog property paths. Expected snapshots were declared from the documented contract, without running Core to generate their expected values. The existing 350 per-key and nine cross-option vectors remain intact for complete validation qualification in WP03-S03.

A [nonshipping C# adapter](../../../implementations/csharp/tests/fixtures/DiscoveryHost/ConfigurationFixtureAdapter.cs) maps logical setup into internal typed inputs and projects actual resolver results. The unit project links that one adapter source; the process host compiles it normally. No new package/project, runtime dependency or shipping public placeholder is introduced. [Table tests](../../../implementations/csharp/tests/CIS.Core.UnitTests/ConfigurationTableTests.cs) execute all 26 rows and a completeness/acceptance coverage check, preserving caller inputs and verifying the 21 exact recognized reads once.

The fixture caller copies a supplied host environment label into setup only when EnvironmentName is unspecified. Core receives a string and has no reference to a mutable framework environment object. Cases retain the original caller host context, while real child processes also record the controlled ASPNETCORE_ENVIRONMENT value before/after Core resolution. This demonstrates preservation of supplied labels and the process variable; it is not an ASP.NET hosted-application integration or a new Core framework/environment lookup.

Four rows vary controlled terminal/debugger context. Those context fields are not injected into Core. A [compiled-call guard](../../../implementations/csharp/tests/CIS.Core.ArchitectureTests/ConfigurationAmbientStateTests.cs) inspects actual CIS.Configuration/CIS.Logging.Configuration method bodies and rejects Console redirect-state queries, Debugger.IsAttached, environment enumeration and environment writes. A never-invoked IL probe qualifies detection of all six forbidden operations. Actual child terminal/debugger state is observed separately, without claiming an attached-debugger execution or complete terminal matrix.

The existing [host](../../../implementations/csharp/tests/fixtures/DiscoveryHost/ConfigurationProcessFixture.cs) adds a configuration mode using genuine entry-assembly discovery, one process-variable capture and the actual Core resolver. The host's fixed application/build facts must match the table. Eight [native integration rows](../../../implementations/csharp/tests/CIS.Core.IntegrationTests/ConfigurationProcessTests.cs) verify full snapshots, unchanged host/framework/parent labels, loaded Core/fixture/input hashes, recognized-name reads and no filesystem output.
