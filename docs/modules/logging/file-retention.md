# Retained segments and restart order

WP05-S06-T02 passes the frozen FileRetainedFiles setting to the existing file worker. Each rotation keeps at most that many listed retained segments plus one active segment. The persistent group GUID is unchanged; the closing active keeps its ID and its exact group-owned closed name, and the new active receives the next positive Int64 ID. The inventory remains strictly ordered by ID, independently of directory enumeration, timestamps or the process that opens it.

The writer computes the complete next inventory before changing any files. If the limit requires retirement, it deletes the oldest exact listed closed/damaged member under the existing group lease before renaming the old active file. It then publishes the bounded next inventory and creates the fresh active path using the existing T01 ordering. Unlisted files, including an unlisted same-group archive, are outside managed retention. There is no wildcard discovery/deletion or new I/O framework. Int64 exhaustion still fails before retirement or rename. A full 1001-entry readable inventory can now rotate at the maximum configured limit of 1000 retained members: it retires the oldest identity rather than growing to unreadable metadata.

A valid existing inventory with more retained members than the selected startup limit fails with safe FileRetentionLimitExceeded before runtime publication. Startup preserves all active, retained and metadata bytes, releases acquired handles, joins its new idle workers and preserves borrowed console streams. Selecting a new group or explicitly archiving the old group is required before using that lower limit. This choice preserves the existing no-deletion-on-failed-startup rule; initialization does not silently prune old data.

Any required retirement or later rotation I/O error terminates the file worker through existing failure accounting and ownership cleanup. Retirement runs before a new retained segment is created, so a deletion error cannot cause further segment growth. An I/O failure or interruption after a successful retirement can leave old metadata referring to a missing member; current startup fails unchanged. Reconciliation remains S07. [T03 terminal file-policy failures](file-policy-failures.md) now add fixed safe categories, independent console progress and defensive Human guards; [T04 physical qualification](file-rotation-qualification.md) now covers at-bound collisions, publication and write failures. Existing damaged inventory members count toward the same bound; creation and recovery of damaged records remain S07.
