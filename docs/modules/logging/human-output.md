# Human output (WP05-S01-T02)

The internal human renderer reads the runtime-owned `EncodedEvent.JsonLine`. It renders the same already captured and bounded v1 facts without accessing the caller, ambient scope/activity, environment configuration, clock or exception again. No public renderer/factory, new dependency or output worker is introduced.

Normal detail contains UTC timestamp, severity, component, event name and message. Verbose adds available service/environment/version, operation and paired trace/span identifiers, allowlisted application/build/instance/process resource facts, structured attributes, supplied raw message-template text and the captured exception tree including type, message, stack, ordered inner exceptions and any local loss markers. Missing optional fields remain absent; originally empty strings remain empty. Resource fields have descriptive labels, such as `resource.build_version`. Human layout and spacing may improve; JSONL remains the versioned machine contract.

Every untrusted string, including structured keys, metadata and exception text, is quoted. Quotes/backslashes and C0/C1 controls are escaped; Unicode format characters (including bidirectional controls, BOM and zero-width characters) and line/paragraph separators use visible scalar-safe escapes. Ordinary Unicode remains readable. Each entry is UTF-8 without BOM and ends with exactly one LF; caller text cannot introduce terminal commands or physical record boundaries. An escaped BOM inside a value is data, not a stream prefix.

The configured byte cap applies to the actual human bytes, including escapes, labels, marker and final LF. The renderer reserves required fields, verbose identity/correlation and an empty message before payload. It clips the message at a complete Unicode scalar/escape boundary. Verbose attributes, exception trees, template and descriptive resource values are retained as complete typed fields in that order when they fit, or omitted with `truncated=true`; smaller later fields may still fit. Atomic field omission avoids changing numeric-string meanings, structured keys or exception types. This display policy is separate from the JSONL encoder's existing greedy payload projection. An unrepresentable protected envelope raises the existing specific internal envelope error rather than emitting oversized bytes.

`RenderedHumanEvent.IsTruncated` includes both captured loss and additional display loss. Normal's intentionally smaller information selection is not truncation. The 64 KiB shared case captures JSONL without loss and renders normal without loss, while verbose escaping omits an oversized attributes field and reports loss. Rendering never changes the original JSONL or its capture flag. The remaining runtime composition task must aggregate render loss into write/global diagnostics before admission; current logger diagnostics still report capture loss only. T02 does not claim that runtime integration is complete.

[Shared cases](../../../conformance/logging/human-rendering-cases.json) cover all six severities, control/injection text, supplementary Unicode, empty/absent optionals and 16/64/128 KiB caps. Unit checks compare the complete display field set and retained resource/payload information and types, verify maximal scalar clipping and argument/envelope errors, and reject corrupted bytes or lost fields/markers. Explicit case expectations require available descriptions to remain whole even when other payload is omitted. Process checks execute the real renderer in isolated exact-runtime children; the independent Python comparator examines original bytes and rejects corruption while accepting field order and spacing changes. Test metadata/time are controlled; activity IDs are the real captured IDs and compared directly without normalization. A synthetic malformed protected envelope is an internal error control, not a valid public event.
