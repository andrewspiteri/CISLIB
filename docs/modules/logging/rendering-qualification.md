# Rendering qualification (WP05-S01-T04)

The internal S01 rendering story is implemented and qualified at the real owned-capture/admission seam. [Combined cases](../../../conformance/logging/rendering-story-cases.json) reuse the actual logger, encoder and admission controls, then render the original `EncodedEvent` objects after caller/configuration changes. They never reconstruct a production capture from a transport DTO. Two consecutive captured records each produce all four explicit format/detail views: JSONL normal/verbose and human normal/verbose. Rendering leaves the original bytes and capture-loss state intact; JSONL views reuse the same memory.

Twenty-one neutral cases cover all six loggable severities, ordinary and supplementary Unicode, composed/decomposed text, bidirectional/zero-width/BOM/supplementary format characters, C0/C1/DEL controls, six newline forms, attempted ANSI/fake-record injection, complete typed attributes and nested exception information, absent versus explicitly empty fields, and 16/64/128 KiB configured caps. Expected identities, UTC times, resources, payload values/types and omission rules are literal fixture data. The test's fixed C# exception type/stack are explicitly named in that catalog; no reflection-derived expectation or nondeterministic normalization is used. None/filtering is covered by the current presentation matrix rather than submitted as a loggable record.

The JSON comparer checks the whole structure, original strict UTF-8 bytes, cap including final LF, no BOM/banner/ANSI/raw multiline prefix, two independently parseable records and exact output-owned tickets. Normal human assertions check precisely timestamp, severity, component, event name and message, plus a visible loss marker when required. Verbose assertions check every available context/resource field and complete captured typed attributes, raw template and exception tree. Already omitted capture fields remain absent. In the cap cases, verbose cannot fit the greedy encoded attributes as a whole display field, so it omits that field and retains protected context with explicit loss. This qualifies the current documented truncation policies rather than silently rejecting oversize input or changing typed values.

Comparers inspect meaning rather than snapshotting JSON property order or human field order/spacing. Positive controls reorder all JSON object maps and both normal/verbose display maps, preserve array order, and change insignificant spacing, including safe leading/trailing ASCII spaces and spaces after `=`. Eleven corruption controls still reject changed schema/time, numbers changed to strings, Booleans changed to numbers, array order, nested exception text, invented optional context, terminal controls, BOM, an extra physical record boundary and copied JSONL memory. Equivalent numeric notation (an integer with `.0`, or floating exponent notation) passes both languages. The [wire contract](../../../contracts/logging/v1/event-contract.json) treats both constructor kinds as JSON numbers and explicitly says wire numbers cannot prove which constructor was chosen. Booleans and numeric strings remain distinct kinds; object keys, strings and arrays remain exact. This is semantic JSON comparison, not an inferred constructor tag or a new lexical wire contract. The controls mutate test transport only and do not claim another production encoding or actual memory-reuse execution.

The native qualification also reruns the complete twelve-row human catalog and sixty-four-row presentation matrix against the same current managed bytes. These add metadata/key/exception escaping, real captured activity bindings and scope changes, display-only loss/scalar clipping, and all explicit format/detail/stream choices across output-enablement profiles. The matrix uses actual logger filtering/capture with explicit non-I/O admission controls; rendering arguments come from the cases. It does not imply that output stream selection or runtime format composition is already wired.
