# Terminal file-policy failures

WP05-S06-T03 retains the existing sequential worker's terminal policy and adds two fixed safe file fault codes. A required exact listed-member deletion that fails with an expected filesystem/access/security exception reports RetentionDeleteFailed. A prepared Human record larger than the actual segment reports RenderTooLarge before any retirement, rename or new active file. Generic writer exceptions still report WriteFailed. The internal typed exception has only private construction and fixed factories; it carries no raw path, payload, inner exception or data. Arbitrary exception data cannot select a policy code.

Retention computes the next bounded inventory before mutations, deletes only exact oldest listed closed/damaged members under the group lease, and does not close/rename/create another segment if required deletion fails. That worker closes file admission, records one attempted accepted entry as failed, abandons unstarted accepted work, releases its handles before completion and preserves the fixed code/UTC fault time after closure. Other outputs remain independently usable; a subsequent call can be PartiallyAccepted by a healthy console while file reports Faulted with no ticket. Runtime closure preserves borrowed streams.

The Human size guard cannot be reached through ordinary valid configured limits: rendered entries are already bounded by MaxEntryBytes and enabled files require FileMaxBytes >= MaxEntryBytes. It remains a defensive writer policy. Tests use real capture/rendering/queues and the physical writer with a deliberately smaller trusted internal segment of 16 bytes, without changing public configuration ranges. They retain the actual prepared Human bytes, prove one attempted write exceeds that limit, and require unchanged empty or populated active/retained/inventory data with no repeated empty rotations. Ordinary oversized caller content still truncates under the user's amendment.

Four primary unit and four integration consumers cover JSONL/Human required deletion failures and empty/populated defensive Human guards. A held file worker admits three actual entries before fault: one fails, two are abandoned, and a fourth remains accepted/written to the healthy console. The failing child probes exclusive active/lease access while its console is still alive, qualifying handle release before process exit. Six semantic matcher corruptions reject at their intended assertions and a generic exception-data forgery remains WriteFailed.

Only verified fresh owned temporary targets are changed: specific Windows victim delete and parent delete-child deny entries, or an unprivileged Unix directory write denial. The parent first proves the actual OS delete fails, releases the worker, independently checks fixed faults, original records/preimages/exact membership and neighbor preservation, then terminates any still-live owned child and attempts every permission restore in finally. Restored Unix modes and Windows ACL output are explicitly compared with their privately captured originals. Raw SID/UID subjects are omitted. Each platform has six primary consumers, two actual denial cases and six specific evidence corruption controls.
