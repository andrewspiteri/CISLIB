# Candidate-package functional consumers

WP07-S01-T02 runs a small consumer with an exact `CIS.Core` PackageReference. It restores into a fresh private feed/package/HTTP cache, shadows parent build settings, uses the pinned SDK and runs under .NET 10.0.12 with roll-forward disabled. The feed contains only the selected candidate and its two approved Microsoft abstraction packages. The restored target must contain exactly those three packages, with no project references. The candidate DLL must match the currently built Core, and every child reports loaded paths, hashes, assembly names, MVIDs, runtime and PID. An altered-origin rejection case qualifies the parent guard.

[The eleven case bindings](../../../conformance/logging/candidate-consumer-qualification.json) execute nineteen process cases. They cover normal/verbose human and JSONL output, separate command stdout, independent thresholds, deferred work, the embedded Microsoft provider, disabled outputs, unsafe startup rollback, concurrent process ownership, kill/restart release, Unicode paths, physical rotation/retention and writer-failure isolation. The application owns Core creation/stop/disposal and uses only public logging APIs.

Recovery tests prepare three exact on-disk transition stages from a real completed candidate-produced segment: intent before rename, renamed with old inventory, and published new inventory. Another case appends a partial JSONL tail. The next candidate process must reconcile the state, preserve the original closed/damaged bytes and continue the group identity. These are controlled physical recovery fixtures, not proof of crashing at a particular instruction or of disk durability.

The pressure test deliberately leaves the child's real stdout pipe unread while a separate private BCL pipe carries control replies and stderr is drained independently. A registered flush must time out with pending work and actual queue-full rejections; bounded input and pending accounting are checked before the parent starts draining. The normal case then drains successfully. The deadline case first freezes an unresolved stop result, then releases the pipe and reconciles later terminal counters with raw output bytes and compares the cached result with the originally returned stop result. A failed, unconfirmed write may have emitted a complete record or a partial tail; those bytes are bounded against Failed and never credited as Written. No arbitrary sleep is used as proof of pressure. The fixture places finite bounds on commands, payloads, processes and observations.

The existing finer-grained source-reference/private-seam tests remain supporting technical cases. This task does not complete coverage, full concurrency reconciliation, discovery/applicability, architecture, mutation, cumulative historical compatibility or final release qualification. BC-009/010 still require the first-release/cumulative compatibility harness. [Task evidence](../../../planning/logging/evidence/wp07-s01-t02/verification.json) records actual lanes, exact inputs, native reports and review outcomes. Runtime code, dependencies, publication history and Type Manager implementation are unchanged.
