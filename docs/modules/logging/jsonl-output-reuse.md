# JSONL output bytes (WP05-S01-T01)

JSONL uses the existing bounded `EventEncoder` and the complete readonly `EncodedEvent.JsonLine`. `CoreLogRuntime.Write` captures facts once, encodes before admission and fans that same object to interested outputs. JSONL output consumers use those bytes directly, including their final LF; they must not add a BOM, banner, ANSI, another terminator or reserialize the event. The existing getter returns the same owned memory. There is no second encoder or renderer wrapper to maintain.

The [shared cases](../../../conformance/logging/jsonl-reuse-cases.json) execute that actual logger/capture/encoding path for all six severities, C0/C1/DEL controls, six newline forms, attempted fake JSON records/terminal commands, Unicode/BOM text inside a value, available/absent/empty fields and three configured caps. Two consecutive events independently parse with exact identity/severity/types. Their bytes retain caller facts after mutation and both admissions share each capture. Joining the actual bytes outside admission is a framing probe, not a writer, queue or delivery implementation. Fixed metadata/time and a declared C# exception type/stack binding avoid nondeterministic normalization.

Ordinary oversize still truncates under the user's policy. These cap cases greedily retain an escaped attribute prefix and mark loss, while omitting exception, template and the two descriptive resource texts once remaining bytes cannot hold them. The protected identities and other metadata/types remain exact. The all-six-byte escaped payload cases must fill within five bytes of the configured cap, rejecting an ignored override or reread of later settings. Literal omitted-field expectations follow the existing [byte priority](event-encoding.md); comparators still check the whole remaining structure. Numeric strings stay strings, explicit attribute null stays null, and unavailable optional fields are absent.

C# and independent Python comparators inspect original bytes with strict UTF-8: no leading BOM/raw C0/C1/DEL or Unicode LS/PS controls, exactly one LF per record, the actual configured cap including escaping/LF, and independently parseable concatenated lines. Nine deliberate framing/encoding/type/stream corruptions must fail; a separately reordered/spaced record must pass structural comparison. JSON member order and insignificant spaces are not a consumer contract. Current cases normalize no nondeterministic fields and never compare timestamp/source/identity loosely.
