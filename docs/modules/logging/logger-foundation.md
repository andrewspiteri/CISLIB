# Runtime-bound logger foundation

WP04-S05-T01 implements `CoreLogRuntime.CreateLogger(component)`, `CoreLogger.IsEnabled(level)`, `Write(level, data)` and `WriteLazy(level, factory)` with real capture and bounded JSONL encoding. Method severity is the only authority; LogEventData has no level property. Loggers borrow their owning runtime and do not own its shutdown. Results have getter-only properties and privately owned read-only output collections, with the already specified enum values and named parameters.

Each runtime owns its metadata, scope store, clock, admission gate, global capture counters and fixed console/file threshold and byte-cap values. It copies the values it needs from LoggingOptions without retaining that mutable object. The general Level supplies inherited thresholds; an explicit Debug file threshold remains interested even when console is Warning and general Level is Information. IsEnabled checks running interest and never reserves capacity. Later option/DTO/scope/activity changes cannot alter the admitted record.

The internal ILogOutputAdmission boundary accepts the same owned EncodedEvent for each interested output. Outputs supply their own successful positive sequence; the logger cannot invent a ticket for a rejection. Disabled outputs are absent, and enabled results stay in console-then-file order. Admission/counter methods must be nonblocking, perform no I/O or caller callbacks, and run no synchronous continuations. The runtime gate spans closure recheck and fanout, preventing a close from splitting an admission. Caller factories, clocks and payload traversal run outside it. Factory exceptions propagate unchanged; invalid capture returns one global safe InvalidEvent before fanout. Owned encoder consistency failures propagate as Core defects rather than incrementing caller-invalid counters. Ordinary oversize truncates under the configured cap and records loss independently of later admission success.

The internal constructor currently binds prepared logging values and real metadata to internal output implementations. Public runtime creation and worker/output ownership are introduced by WP05 composition, and public BeginScope/lifecycle/diagnostics are integrated with their actual runtime implementations. This step adds no public factory/flush/stop/dispose stub. Runtime scopes are exercised through their existing internal store. The console example still identifies the absence of a usable output runtime.

[Shared cases](../../../conformance/logging/logger-foundation-cases.json) run the actual Core methods in unit and isolated exact-runtime process tests. Controlled admission doubles expose interest, acceptance, capacity rejection and tickets; they do not simulate writer delivery. Additional tests check component scalar boundaries, required/undefined arguments, None/closure, caller work outside the gate and owned results. Architecture checks inspect real method bodies, public names/enums and the internal owned-payload boundary. The host emits original bytes as base64 alongside strict UTF-8 text. Both comparators check the decoded original byte count, BOM/LF framing and UTF-8 before parsing records; C# controls corrupt UTF-8/LF/BOM/size. The independent Python comparator rejects missing, wrong and invented tickets plus malformed original UTF-8/LF. A C#-only private-cap fault verifies owned encoder failures are not classified as caller errors. [Retained evidence](../../../planning/logging/evidence/wp04-s05-t01/receipt.json) records final execution.

T02 owns complete argument/early-decision ordering qualification, T03 owns complete lazy/global rejection/outcome/error/counter qualification, and T04 owns the complete outcome table. Real queues, workers, rendering, output faults, flush, shutdown and provider integration remain subsequent tasks. This foundation does not mark S05 or any release gate complete.
