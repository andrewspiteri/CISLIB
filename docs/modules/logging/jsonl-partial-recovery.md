# Partial JSONL segment recovery

WP05-S07-T02 recovers a managed JSONL active file whose final record is partial. Inventory and encoding identity are validated first under the path-group lease. Invalid LF-terminated JSON, BOM, Human partial output and missing/incompatible metadata still fail unchanged.

The owner preserves the entire old file, including any intact earlier records, at .cis-log-<group>-<old-id>.damaged. The group ID stays unchanged and inventory records the old identity as damaged. The fresh active segment uses old-id+1. The lease remains held across non-overwriting rename, complete inventory publication and CreateNew active-file acquisition. No old byte is appended to, truncated or deleted. The existing selected FileMaxBytes check still precedes recovery: an oversized historical partial file fails unchanged with FileSizeLimitExceeded.

Recovery preflights the exact damaged leaf, selected retained count and representable next ID before rename. A visible file/directory collision returns FileRecoveryCollision; a late/inaccessible collision is caught by the non-overwriting move and maps to FileInitializationFailed. Exhausted IDs return FileRecoveryIdentityExhausted; insufficient retention returns FileRetentionLimitExceeded. Startup never retires pre-existing evidence, so a full retained bound fails clearly without growing the group. Existing sparse closed/damaged entries remain unchanged and ordered. Later normal rotation already applies its exact oldest-member policy to both states; full startup/interruption policy qualification remains T03.

Post-rename publication/CreateNew failure handling below is derived from the current source; T02 does not execute those interruption points. Their fixtures and reconciliation remain T03/T04. If the actual transition fails after rename, preserved bytes remain at the damaged path and existing failed private inventory candidates are retained. No appendable fresh active path is created before successful publication. Current startup fails clearly on inconsistent metadata/missing active state rather than guessing a repair; deterministic interrupted-update reconciliation remains T03/T04. No crash durability or exactly-once guarantee is added.

The owner deliberately repeats the bounded Partial check for direct internal callers, rather than trusting the writer’s earlier classification.

The readonly public RecoveredPartialSegment output diagnostic is true only for this runtime's successful partial recovery. It stays true after stop; a new intact runtime reports false while inventory still records historical damage. Console reports false. The runtime freezes this fact before publication, so diagnostic reads perform no file I/O and retain the existing IL boundary. LastFaultCode/time and failed/abandoned counters remain reserved for current delivery failures; recovery invents neither attempted entries nor delivery counts.
