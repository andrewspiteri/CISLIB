# Event and value contract (WP02-S02)

This defines the unpublished v1 contract selected from guide sections 9/13/22, under the user's current architecture. The user amended the original fixed-limit/reject policy to a configurable default and truncation. The language-neutral [schema](../../../contracts/logging/v1/event.schema.json) supplies structural constraints; [the semantic catalog](../../../contracts/logging/v1/event-contract.json) supplies bounds and rules that JSON Schema alone cannot express. C# signatures are a nonshipping reference-only specification. No event logger, capture engine, scope stack or output writer is implemented by this story.

Each captured event combines the immutable process metadata, operation context and event facts. Method-level severity is the only severity input. Six emitted statuses are trace/debug/info/warn/error/critical; None emits nothing. Required fields are schema_version, timestamp, status, event_name, message, service, env, version, component, resource and attributes. Omit absent optional identifiers/template/exception and unavailable resource facts; preserve explicit attribute nulls. Empty messages, templates and attribute maps are valid. UTC timestamps always have seven fractional digits and Z. UUIDs use lowercase D form. Trim optional identifiers before checking length/control characters; blanks become absent.

The resource allowlist contains build_version, instance_id, initialized_at, process_started_at, environment_kind, host_name, os_family, os_description, os_architecture, process_architecture, runtime_description, process_id, commit_id and build_id. The first three, environment_kind and os_family are required. Application name, deployment environment and telemetry version stay at service/env/version. Configuration, paths, destinations, credentials, arbitrary environment variables and exception Data are never projected. A container-visible host name remains application-observed attribution.

Values are explicitly null, boolean, string, finite double, safe integer, integer-string, decimal-string, UUID, timestamp, array or ordinal string-keyed map. Integer construction accepts inclusive ±9007199254740991. Integer-string accepts canonical signed base-10 text without exponent/leading zeros; decimal-string requires an invariant fractional part and preserves its precision. There is no automatic number-to-string conversion, object overload, reflection or arbitrary ToString. A serialized string does not retain its constructor tag; callers must keep a field's representation consistent. JSON numbers alone cannot distinguish an integer constructor from an integer-valued double, so tagged input fixtures check that distinction separately.

LogEventData and OperationContextData are caller-owned named property inputs; LogValue is sealed and immutable with explicit factories. Factories reject malformed scalar representations and own arrays/maps recursively. A wrong/null required argument has an argument exception; invalid scalar construction has ArgumentException/ArgumentOutOfRangeException. Runtime capture truncates oversized ordinary payload before output admission and emits top-level truncated:true. Bounded array/map factories preserve truncation provenance through LogValue.IsTruncated; the final merged attributes and each scope input retain at most the declared nodes/depth. No public captured-event constructor is required: its portable contract is the schema, while queued representations remain implementation details.

Count valid Unicode scalar values, not UTF-16 code units. Reject unpaired surrogates and control characters in identities/names/keys/operation IDs. Attribute root is depth 1 and node 1; every scalar/map/array counts once, keys do not count as nodes. Maximum depth is 8 and nodes 1024. Event/component/key/operation names have 255 scalars; application/environment identities 255; version/build IDs 512. Message and template each have 8192. Scope nesting is 32. CORE_LOG_MAX_ENTRY_BYTES resolves once through EnvironmentOptions to LoggingOptions.MaxEntryBytes (typed LoggingSetup.MaxEntryBytes), default 65536, selected range 16384–16777216 bytes. CORE overrides setup, then default; malformed/out-of-range selected values fail even with disabled outputs. The minimum accommodates the protected identity envelope, and the maximum bounds an explicit override. When a file output is enabled, FileMaxBytes must be at least MaxEntryBytes; otherwise report OutOfRange for the file segment setting at startup. Individual options are still validated when disabled. These range/name choices are prepublication maintainer decisions; configurable default and truncation were requested by the user. The entry limit includes the entire actual escaped UTF-8 record and LF, with no BOM. Traverse/copy with bounds before large secondary allocation. Reserve the protected envelope and top-level marker, then greedily retain message, ordinal attributes, exception preorder, template and optional descriptive resource text. Clip strings at scalar boundaries and omit excess children/whole explicit numeric-string values rather than changing their types. Required message/attributes may become empty. Emit one valid bounded record. A protected envelope that cannot fit raises a specific invalid-event error; ordinary oversized attachments are truncated. Every output must stay within its actual encoded cap, including human escapes. Human output must escape terminal controls; rendering tests remain later work.

An exception has type/message, optional stack_trace/ordered inner_exceptions, and truncated:true only for omitted content. Project in preorder to at most 16 nodes and depth 4, with 4096 message scalars and 16384 stack scalars. Clip on scalar boundaries and mark each node whose text or children were omitted. Exclude arbitrary properties and Data; capture immediately without retaining the source exception. If projection still exceeds aggregate bytes, truncate remaining payload while preserving local and top-level markers.

Scope attributes merge outer to inner, followed by explicit event attributes. A nonblank event operation ID overrides the innermost nonblank scope ID. Attribute names that resemble reserved fields remain nested data and cannot change top-level identity or correlation. Only valid nonzero W3C Activity.Current IDs supply the paired 32/16 lowercase hex trace/span fields. Copy scope data at BeginScope and capture context/activity at event creation. Runtime/async-flow isolation, normal child-task inheritance and LIFO disposal remain required; repeated owner-flow disposal is harmless and out-of-order disposal leaves context unchanged. Forwarded domain events preserve producer attribution.

Producers emit the defined v1 projection. Readers ignore unknown optional fields without accepting changes to required names/types/meaning or schema version. Member order is not a contract. The schema permits additive reader fields; the development validator's producer mode additionally enforces the current allowlist. This is a prepublication design choice, not a compatibility claim against a published baseline.

## Validation and limits

The development-only C# checker evaluates every [record fixture](../../../conformance/logging/event-record-cases.json) using the documented JSON Schema keyword subset and semantic bounds, and every [tagged value fixture](../../../conformance/logging/event-value-cases.json) using explicit scalar normalization. It fails unsupported schema keywords. Raw wire fixtures fix exact escaping, Unicode byte counts, LF and just-at/just-over aggregate boundaries; future serializers must measure their actual bytes even when choosing additional escaping. Native MSTest results count each fixture separately. No third-party schema package enters Core.

[Capture expectations](../../../conformance/logging/event-capture-expectations.json) specify projection, correlation precedence, nested mutation isolation, scopes and exception clipping for WP04. They are not executed capture results. Compiler consumers verify only public shape. Neither these checks nor this story validate another language runtime, a hosted collector, logging delivery or published compatibility.

WP04-S01-T01 now implements [actual C# scalar and owned collection representations](log-values.md). The reference-only signatures still describe the final surface; UUID/time normalization and bounded traversal remain the following tasks.

WP04-S01-T02 adds the actual Uuid(Guid) and Timestamp(DateTimeOffset) normalizers and qualifies the typed object-conversion boundary; see [value guidance](log-values.md) and [retained evidence](../../../planning/logging/evidence/wp04-s01-t02-windows-linux.json). Invalid UUID/calendar and arbitrary-object portable shapes are rejected by the nonshipping typed adapter before Core invocation, rather than represented as public Core string-parser errors. Collection traversal/aggregate entry truncation and shipping serialization remain following tasks.
