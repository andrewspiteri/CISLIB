# Event and scope precedence (WP04-S04-T02)

The actual EventProjection uses the already captured outer-to-inner scope view, then explicit LogEventData attributes. Last matching ordinal key wins as a whole typed value. It does not recursively merge maps, concatenate arrays, fold key casing, normalize Unicode keys or treat explicit LogValue.Null as absence. Null/empty event Attributes preserve the scope view. All eleven typed value kinds can replace a scope value without coercion.

Optional OperationId is trimmed before scalar validation; a nonblank event ID overrides the newest nonblank scope ID. Blank/null inner scope and event IDs do not erase an outer ID. If all are absent, no operation ID is emitted. IDs preserve case and Unicode spelling after trim, accept at most 255 scalars and are never clipped. Leading/trailing whitespace can exceed that bound before trim; controls or malformed Unicode inside a nonblank result remain invalid. Native Unicode whitespace behavior uses .NET String.Trim; neutral cases declare their exact inputs/results.

Producer service/env/version/resource come only from the validated snapshot; component, severity and named event fields come from their explicit inputs. Free-form service/env/version/resource/operation_id/trace_id/span_id spellings remain ordinary nested attributes. Their values and kinds may participate in ordinary precedence, including null; they cannot create or replace protected top-level fields. Event time and actual valid W3C Activity correlation are added by T03, so the complete original CAPTURE-RESERVED-CORRELATION vector and queued correlation evidence remain pending until that capture exists. The current owned-fact observer verifies nested separation, not a shipping encoder or queue.
