# Runtime fanout and successful admission tickets

WP05-S02-T02 connects the actual Core logger/capture implementation to the bounded output workers through an internal `CreateQueued` composition entry. The application-facing factory, physical destinations and public lifecycle remain later tasks. ConsoleHuman remains a scaffold.

Creation copies the effective thresholds, path, queue capacity and entry cap from module options, validates thresholds/capacity/entry cap and both writer-presence choices, then starts the enabled queues. The runtime keeps frozen thresholds/capacity/cap rather than retaining the mutable options. Configure options before creation; concurrent mutation while constructing is not an atomic-snapshot guarantee. Internal writer callbacks receive `AdmittedEvent`, a readonly value slot containing the original immutable EncodedEvent reference and the output's successful Int64 ticket. No extra event/JSONL copy or per-record task is introduced.

The runtime and its queues share one admission gate. Capture, lazy factories, metadata/scopes/time/correlation and JSONL encoding occur before that gate. Under it, the runtime rechecks closure and fans out the same captured object. Each interested healthy queue tries one nonblocking `TryWrite`, publishes its next ticket only on success and returns the explicit admission status. Filtered, invalid, full, stopped and faulted rejections do not allocate a ticket. Each output's successful tickets start at one, remain contiguous and never wrap. C# unit-only private-counter injection qualifies the Int64 exhaustion guard without claiming a real lifetime of Int64.MaxValue admissions: exhaustion terminally closes that output and rejects the incoming event without a negative/duplicate ticket; unattempted queued references are released. Complete S03 diagnostics and abandonment accounting remain pending.

A worker takes a queued slot under the same gate, so it cannot observe tentative ticket publication. It releases the gate before invoking or awaiting the trusted writer. Runtime closure sets its closed flag and closes both queues under that gate; a close cannot split fanout into a healthy accepted console result and a stopped file result. An output's callback failure marks that queue faulted and closes admission under the gate, then preserves the original exception on worker completion. Subsequent normal logger calls return fixed Faulted results rather than that I/O exception. Previously admitted in-flight work may finish; complete failure/abandonment counters, safe diagnostics, flush boundaries, deadlines and disposal remain S03 and later work.

The primitive owns last-accepted sequencing and implements existing filtered/unavailable recording hooks with nonnegative saturating counters. These hooks are useful internal facts, not the complete output diagnostics or Accepted/Written/Failed/Abandoned/Pending snapshot. A successful write result still describes admission rather than confirmed delivery. Independent workers preserve each destination's admission order; shared fanout does not promise a total delivery order between destinations or caller timestamp order.

Twelve shared rows execute actual Core capture, Channels and controlled MemoryStream writes, including successful profiles, inherited threshold union, reject-then-accept ticket continuity, independent saturation, closure/fault during a held lazy factory, early all-fault rejection, frozen settings/captured facts and sixteen concurrent producers. First-writer readiness and explicit release signals replace delay-based ordering; cleanup releases and joins producers and workers. Current C# and independent Python comparers bind confirmed stream bytes and tickets to submitted caller IDs, and compare the original before/after bytes. Concurrent producer results are displayed in successful-ticket order, with actual caller IDs separately retained and checked; no producer scheduling order is assumed. The C# matcher is complementary to the independent Python check: Python additionally checks timestamp, raw carriage returns and successful-ticket contiguity; the recorded coverage does not imply identical standalone validators. Direct tests cover invalid capture, positive Int64 exhaustion at both queue and actual runtime fanout (including earlier queued work released after the terminal fault), same-record output closure races and callbacks closing the runtime from another thread.

The gate observation checks the callback's own monitor ownership, combined with canonical inspection and a bounded cross-thread close from the callback. It does not claim the gate is never held by another producer while independent I/O proceeds. Memory writers and controlled IOException faults qualify the real queue/runtime seam; T03 separately qualifies [incoming overflow and independent results](queue-overflow.md). Actual console/file streams, durability, complete S02/T04 bookkeeping and S03/provider/release qualification remain pending.
