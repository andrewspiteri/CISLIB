# Periodic file flush qualification

WP05-S09-T04 binds all four original S09 acceptance criteria to actual controlled-time Core execution. The source-preserving map is conformance/logging/file-timer-qualification-map.json; it distinguishes criterion evidence from supplemental disabled/range/startup cases. Existing interval, coordination and lifecycle fixtures remain real Core consumers. New terminal probes add no shipping implementation, public API, output worker, dependency or simulated stop result.

The mapped evidence covers one event followed by idle time at minimum/default/maximum intervals and a captured environment override; continuous traffic and actual periodic/public-caller coalescing; blocked writes and flushes with fixed controls and bounded caller state; visible periodic file failures while console continues; and asynchronous callback joins before physical file ownership release.

The interval remains a scheduling target. A blocked writer can delay completion beyond that target. A writer-buffer flush does not guarantee disk durability or collector acknowledgement. Actual writer counters, unresolved controls and callback barriers establish that blocked I/O delays completion beyond the scheduling target; arbitrary sleeps do not establish correctness. The absence of disk-durability or collector-acknowledgement guarantees is a documented contract limit, not an experimentally measured property.

The stopped-rearm and faulted-rearm cases invoke the actual internal queue timer start after its original worker and shared completion have settled. Each makes 64 additional start attempts and advances controlled time by a minute after each attempt. Each inactive extra timer is locally disposed; the original worker, shared completion and disposal task retain reference identity. There is still only one original periodic callback and writer flush, no active timer/control, unchanged terminal diagnostics, and only the original Unicode record. A late write returns Stopped or Rejected/Faulted respectively. This is an internal terminal-guard probe, not a public runtime restart feature.

The existing nonshipping coordination clock is reused through internal accessibility. Its synchronous disposal is adequate for these already-settled terminal cases; it does not qualify an active callback join. The separate T03 physical callback/lease and fault-with-callback cases supply that evidence. Seeded admission exhaustion, private task/reflection probes and controlled MemoryStream writers retain their original documented limits.
