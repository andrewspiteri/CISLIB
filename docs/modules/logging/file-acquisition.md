# Physical file acquisition

WP05-S05-T01 introduces internal `FileOutputOwner`. It consumes the fully qualified path captured by `LoggingOptions.Prepare` or configuration preparation. It creates missing parent directories and opens the physical active file only when `Initialize` runs. Construction/preparation still performs no filesystem acquisition, and a later working-directory change cannot redirect the captured path.

The group uses a reserved empty `<active-path>.cis.lock` companion file. Its open handle has `FileShare.None` and remains owned through the active-file lifetime and later rotation. Acquisition attempts a second handle before opening the active file; if exclusivity cannot be demonstrated, it fails with `CoreLogInitializationException("file", "FileOwnershipUnavailable")`. This also rejects disabled/best-effort Unix locking instead of silently accepting an unowned output. A nonempty companion collision is preserved and fails with the same code.

The active file is opened with `OpenOrCreate`, read/write access and `FileShare.Read`; existing bytes are never truncated or appended by this task. Collectors can open it for reading with `FileShare.ReadWrite`. The group identity is the captured active-path name. Cooperating owners must use its companion lease; aliases that require different companion paths are not a supported way to address one group. Different companion-path aliases are not detected by this protocol and can admit concurrent owners on Unix; file-level symbolic/hard-link identity aliases are not qualified by this task. The lease is persistent: unlinking and recreating it while an owner exists can bypass an advisory Unix lock. External writers or cleanup must not replace the lease while it is held.

Disposal closes the active handle and then releases the lease, including if active disposal fails. Repeated disposal is harmless. Failed acquisition releases any handles it obtained and preserves existing active content, directories, retained files and nonempty companion collisions. Newly created directories and empty lease artifacts may remain; no fallback directory is selected. Lease-open I/O failures use `FileOwnershipUnavailable` even when they reflect a filesystem failure rather than contention; the code means ownership could not be acquired. Other ordinary path/access/I/O initialization failures produce the fixed `FileInitializationFailed` code. These exceptions own only output name and safe code, without inner exceptions or raw filesystem messages. Uncaptured relative/empty internal arguments remain argument errors before acquisition.

This is a physical resource foundation. It does not expose a public runtime factory, append to unvalidated files, create format inventory, start output workers, rotate, retain, recover partial records or promise durability. T02 establishes compatible inventory before any append. T03 composes acquisition with runtime startup and rollback. T04 completes the shared two-process/startup story qualification; S06 and S07 handle rotation and recovery.

Eight focused unit cases and five exact-runtime integration tests execute the actual implementation. Two-process tests block the same group while allowing readers and a distinct group, then reacquire after both clean disposal and a forced child exit. Native Windows and Ubuntu verifiers each execute twenty children, retain original stdout/stderr bytes and check current Core/fixture hashes, Unicode/missing-directory paths, textual dot aliases, preserved existing bytes, collisions, failed-open lease release, parent-file failure and disabled-lock switch/environment controls. Four deliberately damaged reports per platform must fail the intended matcher check. The Linux runs use the retained .NET 10.0.12 runtime under Ubuntu/WSL2 and native `/tmp` files; they do not qualify a Linux SDK, network filesystem, macOS or full release.

The [task receipt](../../../planning/logging/evidence/wp05-s05-t01/receipt.json) records final verification, review, source identities and retained reports. Developer qualification remains distinct from full release qualification; the forty-one planned release cases remain unchanged.
