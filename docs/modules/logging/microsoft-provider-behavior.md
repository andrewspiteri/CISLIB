# Microsoft provider interest and rejection

Current execution strategy, 29 October 2026: the full 14-mode behavior matrix runs directly against Core. Ten physical writer modes also run in exact-runtime children with actual bytes, child PID and lease-release checks. The four controlled no-output/full/fault modes no longer repeat in children because they add no OS or lifetime boundary. The direct argument guards and all physical corruption controls remain.

ILogger.IsEnabled delegates to Core after validating the level. None, no interested output, closed admission, a disposed provider, and all interested outputs faulted return false. A full queue remains interested: Log still formats and captures once, then Core counts each full output without admitting a ticket. Each healthy interested output admits independently; a faulted output does not prevent another output from accepting the same capture. There is no automatic writer retry or replacement.

Log validates the formatter before the level, even after disposal or shutdown. Before either callback, Core applies closure/interest/fault gates. Filtered calls, including Log(None), update existing output filtered counts; all-faulted interested calls update unavailable counts; stopped and disposed calls perform no capture. Provider disposal disables its loggers and leaves application runtime ownership intact. Concurrent disposal/closure after the first check follows the existing Core capture/admission race contract.

The supplied formatter receives the original state and exception once on the caller. Public frontend runtimes contain recoverable formatter failures as one invalid event without state capture or frontend admission; later calls remain usable. The same behavior applies through Microsoft LoggerFactory. A null or invalid Unicode message, invalid event name, unsupported retained state, malformed OriginalFormat, or cooperative state enumeration failure also counts one Core InvalidEvent and admits nothing. ILogger.Log is void and discards Core's result; applications observe loss through Core diagnostics and flush/stop results. Capture callback failures use the existing fixed UnsupportedValue category; malformed adapted templates currently use this same category because the template is supplied inside capture. No exception text becomes a fault category. Argument guards still throw. Catastrophic failures keep their Core behavior. Internal output-only qualification retains its historical exception propagation; earlier receipts describe that older boundary.

Oversized valid payloads are truncated under existing node, depth, scalar and entry-byte bounds. They count as truncated rather than invalid. Root metadata scanning continues under the 1024-entry limit after ordinary value copying stops, preserving Microsoft's final OriginalFormat when visited. At the root only, ordinary keys/values beyond the retained budget are omitted without validation. Nested maps still validate the first observed excess key under the existing Core policy. A template beyond the entry scan guard is also omitted with truncation. The provider numeric EventId is reserved through aggregate node and byte projection, including zero and negative values; caller fields cannot replace it. Duplicate OriginalFormat and nested keys use the last visited value. Supported type/root shape details are in [structured state](microsoft-provider-state.md).

State enumeration is synchronous cooperative caller code. The formatter can itself enumerate a collection before capture; single-use enumerables can therefore fail the second traversal and invalidate the whole event. Materialize them before logging. There is no imposed deadline, arbitrary ToString fallback or reflection serializer.

Fourteen fixture modes and argument-guard cases qualify these decisions. Public physical consumers cover filters, stopped/disposed calls, template ordering, float widening, duplicates/root shapes, unsupported input, capture callbacks and formatter exceptions. No-output, queue-full and writer-fault cases use actual internal Core queues with controlled callbacks, explicit barriers and memory bytes; they do not claim an induced operating-system failure. Independent native readers bind child PID, exact assemblies, raw output bytes and corruption controls. Execution and review results belong in the task receipt.

[Bridge qualification](microsoft-provider-qualification.md) and [host qualification](microsoft-host-qualification.md) bind completed story acceptance; examples/skills and release qualification remain pending. No public API, dependency or worker was added in T04.

Actual LoggerFactory host filter configuration is exercised in [host filtering](microsoft-host-filtering.md). Host suppression precedes Core and cannot appear in its filtered/loss counters; formatter failure containment is exercised by the host story fixture.
