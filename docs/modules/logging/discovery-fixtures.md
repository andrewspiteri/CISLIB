# Discovery tables and process fixtures

> Historical implementation/evidence: the passive caller-populated store in [current guidance](environment-options.md) supersedes these discovery/factory/publication tasks. Original receipts and source proposals remain preserved; do not recreate the removed startup subsystem from this walkthrough.

WP03-S01-T04 exercises Core's internal application, version, runtime and initialization discovery together. The [portable discovery table](../../../conformance/logging/discovery-cases.json) has 20 independently declared input/output rows for Windows/Linux/macOS/unknown projection, missing optional facts, supplied/entry/explicit/Core assembly selection, actual build fallbacks, telemetry labels, explicit IDs, Unicode/case, and separate UTC timestamps. It deliberately does not stand in for the twelve complete public snapshot vectors or static publication.

The [nonshipping host](../../../implementations/csharp/tests/fixtures/DiscoveryHost/Program.cs) calls the actual Core internals. Its informational version is `9.8.7-rc.2+sha.Application`, its assembly version is `23.0.0.0`, and its file-version decoy is `88.0.0.0`. Core retains assembly version `1.0.0.0` and its own different informational version. The real entry-assembly fallback must retain the application name and full informational suffix, never a Core/file version. Loaded application/Core paths and SHA-256 values accompany the native observations.

The `native` mode reads real process start, application-visible machine name, native OS family/description, separate architectures, PID and runtime. The `assembly-version` mode masks only the informational attribute through the existing internal reader seam, proving the assembly-version fallback. The `unavailable` mode explicitly masks both discovered versions and optional process facts; OS family still comes from the actual runtime. These controlled absence modes test unavailable behavior; they do not assert those facts are unavailable on this machine. Required UUID/time generation always runs normally and stays independent of process start.

The maintained [DiscoveryProcessTests](../../../implementations/csharp/tests/CIS.Core.IntegrationTests/DiscoveryProcessTests.cs) retain the seven original integration cases and five observation-corruption controls, plus four explicit-UTC reader cases. They launch real children with 15-second deadlines, independently drained output streams and per-child variables. Every scenario checks exact `.NET 10.0.12`, loaded fixture/Core hashes, static-constructor versus controlled-projection binding, version decoys, UTC times, canonical nonempty UUIDs and native/absent runtime facts. The combined seven-scenario sweep checks unique instance IDs across all seven children and stable application facts across the five native children. The complete parent environment is compared in memory before/after each child; values are never included in the comparison failure message. The class runs without parallel tests so that comparison has a stable boundary.

The project copies the canonical configuration catalog beside the tests. Each child removes all catalogued keys/aliases, then receives only the scenario values and a `DD_AGENT_HOST` collector decoy. Five controls corrupt observations from a successful child and require the validator to reject them. These controls do not mutate shipping code. The Python `verify-process.py` driver is retired; its observations and historical replay boundary are mapped in the [migration record](../../../planning/evidence/corrective-discovery-migration-2026-10-15.md). From the repository root:

```powershell
pwsh -NoProfile -File eng/test.ps1 -Project IntegrationTests -Class DiscoveryProcessTests
```

Use the same entry with PowerShell on Linux, or invoke the C# checker directly from `implementations/csharp`: `dotnet run --project eng/CIS.DependencyChecker/CIS.DependencyChecker.csproj -c Debug -p:RestoreLockedMode=true --no-launch-profile -- focused-test . --project IntegrationTests --class DiscoveryProcessTests`. Use a native pinned SDK/runtime and separate Windows/Linux outputs.
