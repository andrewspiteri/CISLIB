# Complete-record size rotation

WP05-S06-T01 replaces the temporary post-start capacity fault with rotation in the existing sequential file worker. It starts the active byte count from the acquired file's actual length, compares the complete prepared record including UTF-8 escaping and LF with the remaining bytes, and advances the count only after the awaited write succeeds. An exact fit stays active; the next record rotates before any of its bytes are written. This applies to JSONL and Human output independently of console rendering.

Rotation keeps the existing path-group lease held throughout. It computes the next inventory without mutating files, applies [configured oldest-member retention](file-retention.md) before further growth, closes the old active handle, moves that file to the exact closed name without overwriting a collision, publishes complete replacement metadata, opens the fresh active path with CreateNew, and writes the incoming whole record. The persistent group ID remains unchanged; the closed segment keeps the prior ID and the new active ID increases by one. No broad directory matching is performed; retention deletes only exact listed members.

An I/O failure faults the actual file worker through existing accounting and cleanup. A failed rename leaves the prior active bytes and metadata unchanged; any already retired member remains removed, and startup rejects that incomplete inventory until S07 reconciliation. A failure after rename preserves closed data and leaves no new appendable active path until the next identity has been published. Current startup rejects a missing active file with existing inventory. This ordering fails closed for the implemented interruption stages; full recovery/reconciliation remains S07. Metadata candidates are preserved on failure. No crash durability or exactly-once guarantee is added.

A record larger than an empty segment is rejected before rotation, so it cannot produce repeated empty segments. The selected output options already require FileMaxBytes >= MaxEntryBytes; small direct writer tests exercise the internal guard independently of public configuration ranges.
