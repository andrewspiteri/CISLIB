# Owned file-group inventory

WP05-S05-T02 adds internal format-aware `FileOutputOwner.Initialize(path, format)` and `FileGroupInventory`. Acquisition first holds the existing path-group lease. The format-aware overload then creates or inspects `<active-path>.cis.inventory.json`; failed inventory initialization closes its owned handles and releases the lease. Invalid format arguments fail before acquisition. The raw T01 acquisition overload remains internal and does not make a file eligible for append.

If inventory is lost while the active file is empty or missing, a new group is created; old unlisted closed/damaged members are preserved and remain outside its managed retention. A new empty group receives a random persistent group ID, active segment ID `1`, active filename, group format (`jsonl` or `human`), UTF-8 encoding, no-BOM flag and LF newline policy. The writer emits a complete private candidate in the same directory, flushes it, closes it and moves it to the inventory path without requesting overwrite. Publication takes place under the exclusive cooperative group lease. Successful acquisition leaves no candidate files. Failed private candidates may remain, and startup does not delete pre-existing or nonempty artifacts. This is not a power-loss durability or hostile external-race guarantee.

Existing metadata is read without rewriting it. It must have schema `1`, a nonempty group GUID, supported matching format/encoding and a nonempty ordered segment array. Positive segment IDs increase strictly, exactly one final entry is active, and its filename matches the captured active path. The group-wide format and encoding apply to every segment. Unknown optional fields are ignored; duplicate members, unsupported versions, malformed types/JSON/UTF-8, BOM-prefixed inventory and incompatible encoding/newline flags fail. The metadata reader allows at most 2 MiB, JSON depth 12 and 1001 entries (1000 retained members plus one active). These are internal bounds, distinct from the configured log-entry cap.

Closed and damaged entries name exact group members in the active directory: `.cis-log-<group-id-N>-<segment-id-D20>.closed` or `.damaged`. The reader inspects those exact names, preserves their contents, and fails if a referenced member is missing. It does not scan a directory wildcard or read arbitrary paths from metadata. This establishes the identity/naming basis for S06/S07; it does not implement rotation, retention or recovery. Names do not include the active filename so a long valid active filename does not make every closed filename too long.

A nonempty active file without inventory fails with fixed `FileInventoryMissing`; its final newline does not establish format. Malformed or incompatible inventory fails with `FileInventoryIncompatible`. Other inventory access/I/O failures use `FileInventoryInitializationFailed`. All are safe initialization exceptions with output `file`, no inner exception/raw path, and no caller/metadata content. Switching formats at the same path requires a new group or explicit archival, including for an existing empty group, as specified by the original guide.

The owner now records whether the active file was newly created by opening an existing file first and using `CreateNew` only when it is missing. When an active file is missing, the format-aware owner checks for existing inventory under the lease before any creation. Existing metadata makes every retry fail without creating an active file or reusing the lost identity. The inventory reader also rejects a newly created active file paired with old metadata. Valid inventory does not prove every payload byte is valid JSONL or perform partial-record recovery; S07 inspects the final record boundary before recovery. This task does not append, start output workers, expose a public runtime factory or activate examples.

Forty new unit cases and seven exact-runtime integration tests exercise the actual implementation, alongside the existing acquisition tests. The native verifier uses literal independent metadata, retains original child/file bytes, and checks current assemblies, format/encoding rejection, unchanged active/inventory/closed/damaged files, bounded reading, missing active identity and live competing processes on Windows and Ubuntu. T03 wires validated owners into runtime startup; T04 completes the full S05 startup story.
