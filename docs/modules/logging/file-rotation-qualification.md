# Rotation and retention qualification

WP05-S06-T04 qualifies the four original S06 criteria through real internal queued runtimes and native temporary files. The [acceptance map](../../../conformance/logging/file-rotation-qualification-map.json) preserves each original criterion and names its rotation, retention, terminal-failure and supplemental physical-policy consumers. These development cases do not approve the 41 Planned release cases or activate public lifecycle examples.

Rotation now checks whether its exact next closed filename is occupied by a file or directory before retiring any listed evidence. This avoids deleting the oldest segment only to discover a known collision. The final move still forbids overwriting, protecting files that appear later. The lease coordinates cooperating owners; this is not a guarantee against hostile filesystem races.

Eight new consumers cover JSONL/Human collisions with files and directories while retention is at one closed segment, metadata-publication failure, and controlled write failure. Collisions preserve the full active segment, oldest retained segment, inventory and collision bytes. Failed metadata publication follows the existing ordering: required retirement succeeds, the old active becomes its exact closed identity, and one complete private inventory candidate survives. No fresh active file is created. Checks verify the candidate's exact group/format/closed/new-active identities, preserved closed bytes and unchanged neighbors. Startup rejects that inconsistent state safely. Interrupted-update reconciliation remains WP05-S07.

Controlled storage failures use the existing trusted worker callback: the first prepared record is physically written, the next attempt throws IOException, and the remaining unstarted entry is abandoned. This is not an observation of a full volume. The Linux native reader additionally sets RLIMIT_FSIZE to zero only on its own held child after runtime initialization, verifies the effective process limit and releases the worker with SIGXFSZ ignored. The actual file write is rejected by the OS, with no active bytes written. .NET 10.0.12 surfaces that native file-size error as ArgumentOutOfRangeException with parameter value; only this trusted limited-mode fixture accepts that observed exception. The process exits before cleanup; no global limit or host volume is changed. Windows uses the controlled failure plus its real collision/publication/delete-permission consumers; it does not claim an actual full-volume or Unix-limit run.

Every new consumer starts with a missing Unicode directory, performs actual initialization and proves active/lease release while the healthy console remains alive. Three file entries are admitted before the worker is released. File diagnostics distinguish zero writes plus one failed/two abandoned entries from one physical write plus one failed/one abandoned entry. A fourth event remains accepted and written by the console; file admission reports Faulted without a ticket. Fixed WriteFailed diagnostics and UTC fault time survive closure, and stopped lazy factories are not invoked. Borrowed console memory is never disposed by Core.

The independent native comparer checks literal console/prepared records, PID, scalar/escape-safe framing, actual physical leaf membership and original bytes before owned temporary cleanup. Exact transition maps include all foreign-group, unlisted same-group, neighboring and outside-archive files; the held empty lease is excluded from content reads but remains in exact directory membership. Seven specific corruptions must reject at their intended assertions, including the preserved candidate's contents. Existing exact-limit/one-byte-over multibyte rotation, persistent restart/retention and actual deletion-denial cases are re-executed against the same assemblies and readers.

[Task evidence](../../../planning/logging/evidence/wp05-s06-t04/receipt.json) records 4567 passing Developer tests/59 compiler controls, 179 freshly executed native consumers/78 specific corruption controls, original process bytes, read-only Claude initial/follow-up PASS, all resolved criterion/case bindings, 586 source pins, graph limits and indexed byte audit. Public runtime/flush/stop/provider integration, damaged-record recovery, broader advertised-platform execution and complete release qualification remain later work. No new shipping dependency, API, storage framework or retry mechanism is added.

Current WP05-S07-T03 behavior is described in [interrupted file transitions](file-transition-recovery.md). Known pending transitions now resume after byte/identity validation; older states without transition proof still fail clearly. Historical task evidence above remains its original execution snapshot.
