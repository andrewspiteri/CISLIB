# Version selection and initialization identity

WP03-S01-T03 implements internal [application version selection](../../../implementations/csharp/src/CIS.Core/Environment/Resolution/ApplicationVersionSelector.cs) and [initialization identity generation](../../../implementations/csharp/src/CIS.Core/Environment/Discovery/InitializationIdentityFactory.cs). These complement [application facts](application-identity-discovery.md) and [process/runtime facts](runtime-metadata-discovery.md) in Core's `CIS.Configuration` namespace. Public startup validation/publication and complete process fixtures remain later work under the [startup contract](startup-contract.md).

The service-version selector receives actual immutable application identity and reads only `CORE_SERVICE_VERSION`, then `DD_VERSION` if the Core value is absent. A nonblank environment value takes precedence over setup; nonblank setup precedes actual BuildVersion. Values are trimmed while preserving case and suffixes. The returned selection always copies actual BuildVersion separately, and retains the selected service-version source (`CORE_SERVICE_VERSION`, `DD_VERSION`, `EnvironmentSetup.ServiceVersion`, or `BuildVersion`). Deployment labels never alter actual build, commit or build-ID facts. Blank values are absent; a selected invalid nonblank value is retained with its source for later validation rather than silently falling through. This selection stage is not the completed identity validator or startup resolver.

The internal variable interface exposes only one-key reads; its production adapter uses `System.Environment.GetEnvironmentVariable` without enumerating or modifying the process environment. A valid higher-priority Core value does not read the shadowed alias. Variable-access failures propagate instead of using lower-priority setup or build facts. Other settings/aliases, identity bounds and safe aggregated diagnostics remain WP03-S02/WP03-S03.

The initialization factory uses `TimeProvider.System` and `Guid.NewGuid` by default, with injected clock and UUID callbacks for deterministic tests. Each creation invokes the UUID source once, then captures the clock once after identity generation is ready, normalizes the instant to UTC and stores a canonical lowercase UUID string. Results own their values and stay stable when the clock/source later changes. ProcessStartedAtUtc is a separate discovered fact: unavailable process start remains null and a known process start is never changed to initialization time.

The maintainer selected rejection of an empty generated UUID before returning an identity. Required UUID/clock source failures and sequence exhaustion propagate; there is no random/current-clock fallback. The factory has no publication state. The later validated static publisher must call it only for the winning attempt after validation, publish one complete snapshot and preserve this returned identity for that run. These tests do not claim repeated/concurrent public initialization, retry-after-validation-failure or getter publication behavior.

Thirty-seven native unit cases cover the four version sources, blank/trim behavior, preserved suffixes, shadowed invalid inputs, selected-invalid retention, exact variable reads, changing telemetry labels with stable actual facts, variable failures, UTC offsets, canonical UUIDs, distinct per-generation values, immutable ownership, process/init timestamp separation, required-source faults/cancellation/exhaustion, empty IDs, capture order and real default generation. Sixteen concrete `UT-VERSION-*`/`UT-INITIALIZATION-*` bindings require their native methods/counts. The broad `UT-IDENTITY` and complete metadata/publication vectors remain Planned; Linux execution and public static startup remain unqualified. Discovery/generation creates no outputs, workers, logger or external service.
