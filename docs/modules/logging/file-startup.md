# File and console startup

WP05-S05-T03 composes both configured outputs through the internal `CoreLogRuntime.CreateConfiguredQueued` entry. It copies the consumed thresholds, path, formats/detail, entry cap, queue capacity and file bounds before selecting streams or starting workers. Application startup prepares options first; this entry requires an absolute enabled-file path. Public runtime creation and bounded lifecycle remain later tasks.

Each enabled output owns one idle queue/worker. Startup checks borrowed console readiness, then acquires the prepared file path lease and validates or publishes group inventory before returning a runtime. A file-initialization failure closes and joins this attempt's workers, releases acquired file handles/ownership and throws the existing safe initialization exception. Pre-existing active, inventory and retained bytes are preserved; another runtime is unaffected. Borrowed console streams remain open. Startup does not delete existing segments or choose a fallback path.

Producers capture once, prepare bounded bytes independently for each interested healthy output, and queue the original capture with its selected output bytes. JSONL and Human can be mixed. Capture or either display's truncation sets the write result and increments the runtime loss count once. The file worker appends complete prepared records independently of console progress. Its awaited successful write confirms a record; an error uses the existing output failure accounting. Resource disposal happens outside the admission gate before worker completion. No borrowed console stream is passed to owned cleanup.

The active FileStream uses buffer size 1, which [disables managed buffering](https://learn.microsoft.com/en-us/dotnet/api/system.io.filestreamoptions.buffersize?view=net-10.0). Written means completion of the BCL write, without a disk durability claim. Reader handles remain supported by the ownership protocol.

This startup step refuses an existing file larger than the selected limit (`FileSizeLimitExceeded`) or with a non-LF final boundary (`FileRecordBoundaryInvalid`), preserving it. WP05-S06-T01 now supplies [complete-record size rotation](file-rotation.md) for a post-start record that needs another segment. S06-T02 now enforces [configured retention](file-retention.md) and refuses an existing inventory above the selected retained-file bound with `FileRetentionLimitExceeded`; complete deletion-failure qualification remains T03, and S07 must implement the selected JSONL partial-record recovery. The existing startup size/boundary guards remain in place. A final LF does not validate every JSONL record.
