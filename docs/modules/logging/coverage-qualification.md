# Shipping coverage collection

Current preparation and collection use the declared `maintained-csharp-verification-inputs/v1` inventory. They bind maintained C# implementation, tests, build/configuration, invocation glue, contracts, conformance, C# compatibility, documentation, relevant root files and the small explicit plan/baseline/native fixtures read by current tests, without traversing historical archives. Membership and bytes must match before and after collection. Historical replay keeps its separate full repository inventory.

WP07-S01-T04 measures the currently implemented C# shipping code with Microsoft.CodeCoverage 18.10.1. The explicit inventory is [shipping.json](../../../implementations/csharp/verification/coverage/shipping.json): the runtime CIS.Core.dll and the packaged CIS.TypeManager.Build.dll build helper. Both count, although only Core is a runtime dependency. This collection task does not establish release qualification.

Prepare the current candidate once with `pwsh -NoProfile -File eng/verify.ps1 -Profile Developer -PrepareOnly -OutputRoot <new-preparation-directory>` from the repository root (use the optional `-MaxBuildNodes 1` on hosts whose parallel MSBuild workers stall). Then run `pwsh -NoProfile -File eng/verify-shipping-coverage.ps1 -OutputRoot <new-absolute-directory> -VerificationRoot <preparation-directory> -PackagePath <prepared-package.nupkg>` from implementations/csharp. Preparation is recorded as Preparation/prepared-inputs and gives no Developer or release test credit. Collection verifies its current source/input manifest and matching package/inspection, and passes the explicit inputs to every native host. It needs no previous Developer test execution. The prospective `core-and-build-helper-four-families/v2` profile runs all four families, with only the exact Unit empirical-method selection described below. It returns 0 only when both assemblies and their aggregate meet 95% lines and 90% branches; 2 preserves a complete measurement that fails those thresholds. Missing reports/sources, zero assembly branch denominators, failed/skipped tests and inconsistent native counts fail collection. Mutation and cumulative compatibility are separate pending families.

The v2 Unit filter excludes only `CIS.Tests.UnitTests.IncomingMeasurementsTests.RecordQuietFullContendedAndCompleteCallerCosts` (18 current data rows) from instrumentation. Its repeated full-ring observations exceed a billion probes without adding new source/branch identities. All other functional, GC ownership, polling and stress cases remain instrumented, including the held-index ownership method in that same class. The exact filter, omitted method/rows and separate observation obligation are pinned in `shipping.json`, v2 `collection.json`, actual native arguments and TRX. Every shipping source and sequence-point denominator remains required, with unchanged 95%/90% gates. Execute all 52 current observation/stress rows unchanged without instrumentation under a separate 300-second process-tree deadline, as shown in [current candidate acceptance](../healthcheck/current-acceptance.md). Those actual observations are a separate obligation; instrumented timings do not satisfy it. Original v1 receipts remain unfiltered and keep their original policy/input interpretation; mixed or downgraded profiles fail admission.

The candidate archive must contain exactly the two inventoried shipping DLLs, equal to their Release outputs. Inputs, package identity, native TRX/Cobertura attachments, commands and environment are retained. Dynamic managed instrumentation collects child processes without rewriting candidate DLLs; static/native instrumentation is disabled. Real MSBuild architecture cases exercise the actual helper against reusable compiled and PE fixtures, including successful inventory, invalid paths/selections/metadata, satellite/reference rules, conflicts and unchanged-manifest behavior. They add no Type Manager implementation or runtime dependency.

Coverage report interpretation now runs in the existing C# checker (`ShippingCoverage.cs`), replacing `summarize-shipping-coverage.py`. For retained-report analysis, from the language root run `dotnet run --project eng/CIS.DependencyChecker/CIS.DependencyChecker.csproj -c Release -p:RestoreLockedMode=true --no-launch-profile -- shipping-coverage <matching-language-root> <new-output.json> <results-directory> [...]`. Each results directory contains its native `report.trx` and Cobertura attachment. This command evaluates the matching source project's Compile items with a finite child deadline, preserves the existing observation schema and returns 1 for invalid input, 2 for measured threshold failure, or 0 for qualified measurements. It cannot turn historical reports into current-candidate coverage; use the full collection entry above for that boundary. `ShippingCoverageTests` supplies 28 native parser/aggregation controls. See the [migration evidence](../../../planning/evidence/corrective-coverage-migration-2026-10-15.md).

The collector includes auto-properties and has no implicit or explicit source, method, attribute, company or key exclusions. Async/state-machine and other executable compiler transformations remain counted. The individually inventoried enum/interface/constant-only source files have no executable sequence points, including the declaration-only `ILogWriter` and Healthcheck interfaces. Their hashes and reasons remain in the inventory. Any unexpected executable source, omitted handwritten file or non-executable declaration that acquires sequence points fails validation. The source set is compared with evaluated MSBuild Compile items for each project. SDK-generated assembly metadata contains no handwritten executable body; no generated executable source is excluded from these reports.

Native class/source/line identities and branch denominators are preserved, including multiple native class entries on one physical source line. Line execution is unioned across reports. Cobertura supplies covered branch counts without stable identities for each outcome, so the summary takes the maximum covered count per line across reports. This is a conservative lower bound: complementary outcomes in separate reports receive no invented union credit. Assembly totals and the aggregate sum those counts and denominators. No OS lanes are merged. A known branching SeverityTokenParser fixture must have a nonzero measured/covered branch denominator.
