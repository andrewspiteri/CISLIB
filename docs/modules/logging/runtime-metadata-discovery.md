# Process and runtime metadata discovery

> Historical implementation/evidence: the passive caller-populated store in [current guidance](environment-options.md) supersedes these discovery/factory/publication tasks. Original receipts and source proposals remain preserved; do not recreate the removed startup subsystem from this walkthrough.

WP03-S01-T02 implements internal process/host/OS/runtime facts in RuntimeMetadataDiscovery (removed by simplification), in Core's `CIS.Configuration` namespace. It complements [application identity discovery](application-identity-discovery.md). These are genuine Core internals for the later resolver, while the [public startup contract](startup-contract.md), snapshot publication and logging runtime remain pending; initialization generation is implemented separately.

The default runtime source (removed by simplification) reads the current process's start time, application-visible machine name, OS family/description, OS/process architectures, framework description and process ID. It disposes the temporary `Process` object after reading start time. It never reads `DD_AGENT_HOST`, deployment version variables or arbitrary environment values. Host name describes what this application sees; it does not identify a container's physical host or a collector.

Process start is the actual nullable discovered instant, converted to UTC with zero offset. It never uses initialization/current time as a substitute. The standard [Process.StartTime API](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.starttime?view=net-10.0) can report native/platform/process availability failures. The shared optional reader now supports nullable value facts as well as reference facts, and its explicit discovery-failure filter includes `Win32Exception`. Each read is isolated: a missing start or host does not erase available runtime/OS/PID facts. Unexpected programming faults and cancellation propagate.

OS family is `windows`, `linux`, `macos`, or `unknown`; an unavailable/unrecognized platform uses `unknown` independently of its optional description. Optional text is trimmed with case/internal characters preserved, and blank text stays absent. The [runtime architecture enum](https://learn.microsoft.com/en-us/dotnet/api/system.runtime.interopservices.architecture?view=net-10.0) maps defined values to lowercase names, separately for OS and process. Before publication, the maintainer selected unavailable/null results for undefined architecture values and nonpositive process IDs; positive IDs retain the event contract's integer range. These are observed facts, not operator configuration overrides or new supported CPU/platform lanes.

An internal typed source supplies deterministic tests. Discovery captures eight facts once into an owned immutable value without retaining that source. The 55 native cases cover Windows/Linux/macOS/unknown family recognition, all ten .NET 10 architecture names plus unavailable/undefined values, separate architectures, PID bounds, four timestamp offsets, optional/blank facts, copied ownership, independent native failures and unexpected faults/cancellation. One case uses real current-process/runtime APIs. The current execution is Windows x64; injected Linux/macOS families and other architecture values are unit cases, not execution qualification. No global process environment or system clock is changed by these tests.

T02 implements the process-fact portion of the twelve portable metadata vectors. The whole `UT-IDENTITY` group stays Planned: service/build version resolution and initialization identity/time are T03 work, complete process fixtures are T04 work, and public snapshot publication follows in WP03-S04. Linux and macOS execution remain unclaimed. No output, worker, external service, logger or serializer is created by discovery.

WP03-S01-T04 adds [combined discovery tables and actual Windows/Ubuntu process fixtures](discovery-fixtures.md). The original T02 evidence remains Windows-only; the new Linux scope is actual discovery on Ubuntu 24.04 WSL2, without Linux SDK/full-suite qualification or a macOS execution claim.
