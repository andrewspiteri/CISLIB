# Output accounting foundation

WP05-S03-T01 adds internal cumulative accounting to the actual Core/Channel workers. Each enabled output owns Filtered, Accepted, QueueFull, Unavailable, Written, Failed and Abandoned. Rejected is the sum of QueueFull and Unavailable; AdmissionAttempts also includes Accepted. Filtered, invalid captures, factory exceptions and stopped calls do not create an output admission attempt. The existing runtime-wide InvalidEventCount increments once for invalid capture before fanout, regardless of enabled output count.

`CaptureAccounting` returns a small readonly value under the existing admission/dequeue lock. Pending includes buffered events and the one unresolved in-flight event; InFlight is a subset of Pending, never an additional accepted record. The older internal queue-depth hook is now named BufferedCount. Historical fixture transport fields named pending still measure only that explicitly documented buffer depth, preserving their original cases/evidence.

Successful admission increments Accepted with the published ticket. Dequeue changes only the in-flight gauge. A successfully completed trusted writer callback increments Written and resolves that in-flight record. A throwing callback increments Failed, and terminal worker cleanup counts each not-started queued record as Abandoned under the same lock. Sequence exhaustion also abandons buffered records when the worker exits; an already started callback remains Pending until it actually completes. The original exception remains observable through worker Completion. No writer/caller work runs under the lock, and no retry, replacement worker, public placeholder or additional runtime dependency is introduced.

Every real output observation satisfies `Accepted = Written + Failed + Abandoned + Pending`. Pending can decrease; cumulative counters cannot. Accepted/tickets stop at Int64.MaxValue, so their disposition identity remains exact. Independent Filtered/QueueFull/Unavailable loss counters saturate at Int64.MaxValue, retaining a lower bound once their totals cannot be represented. Rejected and AdmissionAttempts are saturated sums of their components. Thus `AdmissionAttempts = Accepted + QueueFull + Unavailable` is exact while the sum is representable; above that limit its defined observation is Int64.MaxValue. Artificial unit-only private counter/ticket seeds do not establish executed prehistory.

[Eleven literal scenarios](../../../conformance/logging/output-accounting-cases.json) cover individual/both/disabled outputs, threshold filtering, queue fullness, two globally invalid captures, original factory failures, held in-flight/queued work, one-sided/all-sided terminal faults, subsequent admission, closure and complete drain. Writer readiness/release barriers make each checkpoint deterministic, and cleanup releases and joins every worker. Early readonly snapshots are retained and projected after the final drain, proving they do not drift with live counters. Independent C# and Python comparers check the partition, saturated admission sums, gauge bounds, cumulative monotonicity, literal outcomes/tickets and writer attempt counts, with nine corruption controls. C# unit-only controls cover saturation, 64 concurrent admissions while the first writer is held, and the held/final accounting partitions for two actual admissions after a private near-limit ticket seed.

This implements T01 accounting at the internal controlled-writer seam. Complete/partial/uncertain physical write interpretation and broader boundary observations remain T02. Output state transitions and retained safe fault codes/times remain T03. Public GetDiagnostics and complete S03 qualification remain T04; flush/deadlines/resource ownership/provider/release are later work. A completed memory callback does not prove disk durability or collector acknowledgement.
