# Complete-write confirmation and live observations

> Current status, 17 October 2026: runtime, output and provider implementation and the native C# reader migrations are complete development work. Historical receipts retain their original source and do not qualify the current tree.

WP05-S03-T02 gives the actual queued runtime one internal readonly observation of admission closure, global InvalidEvent/TruncatedEvent counts and both enabled outputs. Each output value includes its accepted sequence alongside the existing accounting fields, captured together under its gate. The runtime holds the shared fanout/dequeue/disposition gate across both output reads. Output state and truncation are stable during that lock; the independently atomic InvalidEvent read selects the observation point. Disabled outputs are absent. Admission-only controls cannot invent observations: that nonqueued internal composition rejects this accounting request.

These are owned live boundaries. They do not register a flush request, retain per-sequence history, wait for I/O or schedule a task. Registered nondroppable flush boundaries and counts through a fixed historical target belong to WP05-S08. Public GetDiagnostics belongs to T04; state/last-safe-fault information belongs to T03. No new public surface or dependency is introduced.

The existing worker increments Written only after its trusted complete-record writer callback returns successfully. Dequeue and emitted bytes do not confirm success. A callback still unresolved remains Pending/InFlight even if all bytes have already been emitted or cancellation has been requested. A terminal exception, including cancellation, counts the attempted record Failed, with not-started queued work Abandoned on worker cleanup. Partial or even complete bytes may exist after a terminal failure; neither implies a confirmed complete write. The worker preserves the original exception and does not retry. A writer supplied by later physical console/file composition must uphold this complete-record callback contract.

[Eleven literal shared cases](../../../conformance/logging/delivery-observation-cases.json) run actual Core capture, ticketed Channels and asynchronous controlled Stream.WriteAsync operations against a memory sink. Each stream emits zero, half or all of its first owned JSONL record, signals readiness and holds completion. Further accepted records stay queued. Explicit cancellation requests are deliberately ignored until the controlled operation resolves, demonstrating uncertainty rather than a runtime stop/deadline implementation. Releasing one closed output proves the other remains independently unresolved. Complete success, partial/full-byte terminal IOException, terminal OperationCanceledException and successful completion despite an earlier cancellation request are classified by actual callback outcome. Cleanup releases and joins every worker before disposing streams.

Readonly initial/held/cancel-request/closed/one-terminal/final runtime values are retained and projected only after drain. Literal global/output counters and complete per-call outcomes are checked independently of live fields. Separate C# and Python comparers qualify counter/ticket identities, monotonicity, pending/in-flight bounds, original immutable bytes, per-output attempted/confirmed ticket order, shared event bytes, strict UTF-8/LF/no-BOM bounds and exact emitted prefixes/complete records. Ten corruption controls reject premature confirmation, lost in-flight state, falsely confirmed partial/full failure, cancellation-as-terminal before resolution, snapshot/ticket drift, retries and byte corruption. C# unit-only controls sample 502 live boundaries around 128 concurrent valid admissions plus 32 invalid captures while both writers are held, qualify original synchronous failure, and reject invented facts from admission doubles. The bounded samples and canonical locking source establish complementary evidence, not an exhaustive interleaving proof.
