# Blank values, tokens and identity text

WP03-S02-T03 qualifies the normalization behavior used by [captured input selection](configuration-inputs.md) and [typed resolution](configuration-resolution.md). The existing production mechanisms already implement the required behavior; this task adds full-resolver controls and documents their scope. It does not add a second normalization path or change the accepted severity abbreviations.

Null, empty and whitespace-only configurable strings are absent. Every CORE setting can therefore fall through to typed setup/defaults. The three identity aliases also fall through when blank, followed by blank setup text and discovered/documented defaults. FilePath remains absent when its available text sources are blank. C# uses `string.IsNullOrWhiteSpace` and `Trim`; controls execute ASCII space, tab/CR/LF, nonbreaking space (U+00A0), em space (U+2003), narrow nonbreaking space (U+202F) and ideographic space (U+3000). Zero-width space (U+200B) and BOM (U+FEFF) are not treated as whitespace or silently stripped.

Nonblank text loses only surrounding whitespace. Identity, version and path text retain case, internal whitespace and Unicode sequences, including decomposed combining characters. No case folding or Unicode composition is applied to those values. Actual BuildVersion stays independent of service-version labels. Caller setup strings and framework labels remain unchanged.

Configuration tokens use case-insensitive, culture-independent recognition. Severity uses the proven invariant parser with the user-selected aliases; format/stream/detail use ordinal case-insensitive token maps. Full-resolver controls exercise lower, upper and alternating case with Unicode padding under en-US, tr-TR and ar-SA. Internal whitespace, zero-width characters, numeric-token syntax errors and unrecognized nonblank values remain selected errors. They are not repaired, treated as absent or replaced by a valid lower-priority value.

Capture requests only the 18 catalog CORE names and three supported DD aliases. It does not enumerate variables or request unknown credentials, optional-provider settings, DD_AGENT_HOST, framework settings, misspelled names or Unicode lookalikes. Owned snapshot lookups are ordinal; the underlying variable source's operating-system lookup semantics are not overridden. Unknown names and values are not retained. Plain object formatting of captures, parsed results and settings does not automatically print raw input values, and reading an invalid parsed value produces a generic guard error. This is not the future public aggregated diagnostic contract, which is WP03-S03 work.

Fifty-one native cases bind nine methods to these behaviors, including all 18 settings with seven blank forms, all identity source layers, 14 token rows with nine culture/case combinations each, ten malformed nonblank tokens, two non-whitespace format characters, six unknown names, safe formatting and input ownership. [Windows evidence](../../../planning/logging/evidence/wp03-s02-t03-windows.json) retains direct Developer verification, raw reports and isolated source replay. Existing parser, input, discovery and resolver cases continue to run.

WP03-S02-T04 still needs shared input/output configuration fixtures. The 350 complete per-key and nine cross-option expectations remain pending full resolver/validator qualification. Option ranges, required identity/control/scalar checks, path syntax/absolute resolution, safe aggregated errors and public snapshot publication remain later work. No complete Linux SDK/test-family or release qualification is claimed by these C# Windows controls.
