# Controlled scheduled source tests

`CIS.CommonTesting.ScriptedJobRunSource` substitutes the public `IJobRunSource`
port with independently bounded ordered scripts and call recordings, initially
sixteen each. It advertises only `ExternallyAdmittedOccurrences`. It performs no
authentication, authorization, SQL, durable admission, acknowledgement or calendar
evaluation. A scripted admitted result is a test input, not durable proof.

Queue `EnqueueValidation(expectedRun, result)` or
`EnqueueFailure(expectedRun, exception)`. Validation requires matching complete
metadata, original operation, input digest/length and the exact immutable settings
reference. A mismatched call, full recording capacity or pre-cancellation consumes
no next script. Scripted exceptions preserve their original identity.

Scripts and recordings retain bounded detached metadata, settings and a 32-byte
transport digest. They do not retain `EncodedMessage` instances or payload frames.
`Calls` returns a detached read-only snapshot of the bounded recording list. No call
history is generated by collection or runtime inspection.

This controlled trigger explicitly submits one known occurrence, then submits it
again with unchanged occurrence and original operation identity:

```csharp
using CIS.CommonTesting;
using CIS.Jobs;

// The application supplies catalog, executionScopes, configuration and run.
// run is an immutable Command admission with SourceId "controlled-source".
var source = new ScriptedJobRunSource("controlled-source");
await using var runtime = new JobRuntime(catalog, executionScopes, configuration, source);
await runtime.StartAsync(cancellationToken);
IScheduledJobDispatcher dispatcher = new ScheduledJobDispatcher(runtime);
source.EnqueueValidation(run, new JobAdmissionValidation(true));
ScheduledJobResult first = await dispatcher.DispatchAsync(run, cancellationToken);

source.EnqueueValidation(run, new JobAdmissionValidation(true));
ScheduledJobResult redelivery = await dispatcher.DispatchAsync(run, cancellationToken);
```

Use `JobScheduledActivation.ExternalOccurrences` for this setup. Displaying a
Daily/Weekly descriptor does not arrange recurring execution. The example has no
calendar evaluation, next-run calculation or durable retry loop. A handler using
the original RM-03 journal can return PreviouslyCompleted on redelivery; the source
helper itself does not recover results.

The ordinary scheduled tests use the existing `ManualTimeProvider`, explicit
controlled tasks and real DI scopes to verify local pressure, authorization,
immutable admission, actual callback/scope settlement and terminal result facts.
The helper tests use public contracts only. SQL exclusivity, transaction atomicity,
authentication and broker durability require their separate real-provider evidence.
See [scheduled ownership](scheduled.md) and
[CIS-0022 verification](../../changes/CIS-0022/verification.md).
