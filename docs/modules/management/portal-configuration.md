# Configuration authoring and coherent releases

The current R09 desktop surface is the [single Configuration versions page](portal-configuration-versions.md). The R08 controls below remain historical execution/recovery context; their multi-step UI is superseded. Native publication, coherent-release and assignment contracts remain separate.

Open **Edit**, **Override** or **Publish…** through an application's exact Configuration row menu or JSON detail panel. The current R08 main editor changes the Application layer only; an explicit Common link remains read only. The editor binds the application, environment, Configuration ID, schema, host scope and actual source. Current read permission does not imply publication, release or original-result permission. Declared defaults and selected publication content remain independently protected; redacted or unavailable content never becomes an empty object or an editable mask. The [JSON workflow guide](portal-configuration-ux.md) describes the simplified surface and real predeployment creation.

An unassigned binding has no selected source baseline, even when its source has immutable history. The source's ETag protects its publication catalog; UUID-ordered history is not a current-value pointer. Choose exact Common/Application publications from bounded history, retain the actual assignment-pinned pair when supplied, or deliberately choose absence. A new empty override is an explicit choice. Both layers stay pinned during review; opening history creates no effect.

The raw draft alone is bounded to 256 KiB UTF-8 and depth sixteen and remains in memory. The main surface is one large JSON textarea rather than generated typed controls or source-reference selectors. Numeric values are never round-tripped through JavaScript `Number`. **Format JSON** copies the original quoted strings and value tokens while changing whitespace only. Member order, unknown members, large numeric tokens, exponent spelling, Unicode escapes, false, zero and null retain their exact tokens. Explicit null differs from omission. The current shape contract supplies no duration units, executable components or runtime update mode, so none are inferred.

Only the existing Configuration lexical validator determines raw JSON admissibility. The formatter is not another schema engine, merge implementation or validator authority. Omitted fields are not filled by a browser merge. Authorized declared defaults can be inspected separately and are not presented as accepted/effective consumer values. Editing or formatting invalidates previous review; incomplete JSON cannot obtain a new native review. Auxiliary reference/reason intent uses the existing protected-state dirty flag without wrapping or changing payload bytes.

**Validate JSON** performs the native structural check. **Review publication** uses the actual candidate-preview companion before any publication. It freezes exact source/map ETags, both baseline references, payload SHA-256 and current binding/environment/host identity. Effective changes compare with the native current default assignment. Protected impact or structural issues prevent confirmation; consumer semantic acceptance remains unknown. The displayed recipient page is bounded and is not a fleet acceptance result.

**Confirm immutable publication** first retains a separate minimal original reference and submits the exact reviewed bytes once under the source ETag. A committed publication is not assigned or active. Only a known native applied result supplies a real publication identity. The operator can then explicitly advance to a separate release review, choose the complete coherent pair and confirm **Confirm coherent release — not assigned** under the current map ETag and a different original key. Existing exact publication references can also be reviewed and released without creating any new publication. This editor submits no assignment or activation operation.

Publication and release retain separate original observations so a later uncertain release does not erase a known publication. Original recovery selects its exact target before admission, invokes the native same-key lookup directly, and joins the actual callback/cleanup. It performs no application/definition prefetch for recovery and never reconstructs a command from receipt storage. Once a known observation is displayed, another lookup cannot replace it until explicit dismissal or the finite publication-to-release advance. Unknown, missing, expired or denied results never authorize an automatic replacement operation. A still-permitted draft/reference choice survives a known conflict for refresh and deliberate review.

Before admitting a lookup, the editor lets already-issued background readers and their local state application settle, including denied or unavailable results. It starts no new read and does not require read success. The stable logical read target and original-lookup target are selected before admission, so a delayed read initialization cannot cancel that same-view lookup. A genuinely changed session/target still cancels and joins the callback. Publication history is closed while an original is retained. The retained source-publication recovery failure prompted this ordering review; authored real-owner tests cover target-selection cancellation and lookup-only recovery after a denied background read. The saved browser failure alone does not identify the exact cancellation source.

Reload retains only minimal same-operator/service original references. In particular, a shared Common-source receipt is not an application association or a saved release intent. Advancing from a recovered publication requires current binding data and explicit complete reference review. Session/target changes and permission loss clear affected protected values; an incoming foreign application/configuration/schema/source tuple is hidden during render and clears the draft, review and open history. A transient outage retains only permitted dated state and disables new submissions. Cancel, Back and ordinary document navigation use the existing dirty guard for payload and auxiliary intent.
