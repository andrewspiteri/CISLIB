# Application display metadata

The application detail page's **Display metadata** link opens a document-scoped editor. Application identity, environment and application ID remain fixed. The page independently reads current native metadata and advisory capability hints; changing metadata requires both the actual application write grant and original-result lookup grant. A readable application can therefore have a read-only metadata view.

Display name and description use the existing native scalar limits: 1–256 and 0–2,048 Unicode characters respectively, without control characters. Text is preserved without trimming or Unicode normalization. Clearing the description is explicit in the review and sends native omission-to-clear rather than `null`. The review binds the exact command and current metadata ETag. Cancel, Back and document navigation require confirmation before discarding a dirty draft. Drafts and preconditions remain in memory and are never put in receipt storage.

Confirm first retains and verifies the shared minimal original reference, then submits one same-origin authenticated PUT. The BFF passes the original key, strong `If-Match` and closed native `MetadataCommand` to the actual Management client; it does not provide a second metadata store or authorization decision. Direct requests use the same CSRF, session, target and native grant checks. Raw request JSON is validated before parsing can normalize version-number tokens or duplicate members.

A fresh confirmation returns to the exact application's Instances page only after its prepared key, current session, target and unchanged reviewed draft match a known committed applied result. It clears that committed draft, while retaining the payload-free original reference for later inspection or explicit dismissal. A historical recovered result never triggers automatic navigation. Unknown delivery, conflict, changed drafts and changed sessions stay in the editor. A known commit with unresolved client or native-attempt cleanup stays visible with separate cleanup facts instead of being hidden by navigation. Back to application uses the same canonical Instances route and exact application selector; dirty Back/Cancel still require the existing deliberate discard decision.

A decoded original result is distinct from the current transport and cleanup facts. Only a known committed applied result is displayed as committed metadata. A committed rejection remains rejected, including a stale-ETag conflict; unknown, missing, expired, denied and not-committed observations never authorize a replacement key. The browser queues no writes and does not retry a mutation automatically.

After a lost response or reload, **Recover original result** directly invokes the actual native lookup for the retained application and key. It has no application-read or metadata-editor prefetch gate. Native actor scope still applies: an operator cannot use another operator's original key. The same actor can recover its original after its application-read and write grants are removed while its original-result grant remains. No draft can be reconstructed or resent from a receipt. Lookup denial clears affected draft values while retaining only the permitted minimal reference.

The browser selects the exact application/key lookup target **before** admitting receipt recovery. Target changes intentionally cancel an existing recovery, so selecting a new target inside an already admitted callback would cancel that callback's own signal. The finite metadata recovery helper establishes the target first, refuses a concurrent recovery without changing its target, and retains both the receipt selection and request custody until the actual callback settles. Cancellation changes visibility and signals; it does not release pending work early.

A resolved reference is dismissed only by an explicit action. While its known original observation is displayed, further recovery is blocked for every receipt so another read cannot overwrite that fact. A known not-committed observation is also retained until explicit dismissal and fresh review; it queues no replacement. Conflicts retain a still-permitted in-memory draft, refresh current metadata, and require a new deliberate review using its new ETag. Applied changes refresh from native state before another edit. Session changes, expiry and sign-out use the shared protected-state owner to clear old values and suppress late responses; transient failures disable new submissions and retain only permitted dated state.

The existing controlled-issuer/native Management fixture covers strict request grammar, CSRF/context rejection, real grants, ETag conflict, original lookup and actual Audit records. Its desktop continuation covers keyboard review, clear-description semantics, dirty document Back/Cancel, and a delivery-loss case that first executes a real native PUT, drops only its response delivery, then reloads and recovers the same original key. The delivery fault is explicitly labelled controlled. C# checks the actual resulting metadata revision and one native Audit per original effect/rejection. Authored checks and this guide are not substitutes for the task's captured native results.
