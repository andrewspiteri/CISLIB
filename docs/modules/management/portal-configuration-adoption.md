# Configuration instance status

Open **Instance status** for one exact application, Configuration ID and schema, or expand it on the Configuration version page. Both entry points share the same three columns: **Instance**, **Configuration version in use**, and **Status**. The page reads the existing binding-scoped adoption API directly under current native AdoptionRead authority. It does not require an application/definition/content prefetch, infer permission from a link, load source values or scan every instance/page. A denied, unavailable or unsupported backend read remains a visible read failure; it does not become an empty successful rollout.

Configuration version in use means the consumer's recognized, valid last reported applied release. An independently authorized saved note/date labels that exact immutable release; it is never an app version, inferred ordinal or assignment generation. Missing applied data says **Not reported**. Unsafe or unknown report semantics say **Current version unknown**. Missing, restricted or off-page version metadata says **Version details unavailable**, while the observation remains visible. The standalone page optionally reads one existing release-history page of at most 100 rows; it does not follow its cursor or fetch metadata per instance. The inline table reuses already loaded metadata. No content read is added. Human dates use the browser's local time zone; exact original UTC timestamps remain in Technical details.

Known fresh native convergence and recognized report facts support **Up to date**, **Needs restart** or **Failed**. Pending assignments remain **Pending**; stale/offline/earlier/missing/unknown observations remain neutral **Unknown**. A fresh receipt does not repair an offline registration or prove uninterrupted live execution. Notification failure alone is not Failed. A known historical Faulted report cannot override current unknown convergence. Native noInstances means **No observed instances** for that target, not successful adoption or absence of physical processes. An empty authorized page remains an empty page.

Selecting an instance opens the existing right-side panel with simple status, reported version in use, desired version at that read and report time. All native diagnostics remain in default-closed **Technical details**: app version, independent registration/report freshness, update mode, raw convergence/state tokens, exact desired/reported/applied/local revision fields, historical last-successful acceptance, candidate/notification failure codes, original timestamps and resource identities with Copy. Exact integer strings, including local revision zero, remain intact. Historical success never fills a missing applied version or establishes safe current live values. Selection uses exact cohort/registration identity within the fixed application/Configuration/schema, not instance text. Close/Escape restores focus to its row or heading. Paging, refresh, scope/session change and permission loss close or clear selection through the existing protected owner. Earlier pages are explicitly qualified; their retained native facts are never rewritten as synthetic stale/offline values.

Every page is a separately authorized observation, not a frozen fleet snapshot. Only rows with an actual registration appear as clickable instances; native unregistered/noInstances target facts remain in one closed Technical details section. The pager counts only registered instances on this page and displays no fleet percentage; its native cursor is unchanged. A page with no registered rows is an empty instance page, even if it contains target diagnostics. No separately read assignment map is overlaid as though it were atomic with these observations. Refresh can observe another desired generation. The view sends no assignment, restart, report, command or Audit effect and adds no scheduling/runtime behavior.
