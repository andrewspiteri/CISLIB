# Configuration assignment maps

Open **Manage assignment map** from a Configuration definition, or deliberately continue from a known committed release. Publication and release creation never assign automatically. **Inspect Configuration adoption** is a separate read of recipient observations; a committed map is not a restart, deployment or consumer acceptance result.

The editor captures one complete native map, including its exact binding, environment, schema, ETag, default, generation and every cohort pin. Existing pins remain present even when an independent release detail is protected or outside the current selector page. Missing details do not become removal. Retained releases are selected from bounded authorized pages or an exact authorized release read. Their actual creation time, reason and actor are shown; UUID order and generation are not release versions. Cohorts come only from the native trusted-choice read. The browser cannot create a cohort or edit membership.

**Canary** retains an existing default and all unrelated pins while changing one explicitly selected cohort. An unassigned map requires an explicit default. Changing an already edited Canary target requires deliberate discard rather than silently accumulating unrelated edits. **Promote** and **Rollback** show the whole current/proposed union and permit explicit retained, replaced and removed pins. Removing a pin means inheritance from the proposed default. A retained earlier release can be chosen for rollback; each successful new decision advances generation once. Exact integer arithmetic is used only for the tentative next generation; the native owner decides commitment and exhaustion.

**Review complete assignment** sends the existing side-effect-free native preview. Its entire current map and ETag must equal the frozen baseline, and its proposed intent, default, reason and complete pins must echo the draft. Structural refusal prevents confirmation. Protected effective source values do not prevent an otherwise authorized metadata-only map decision; the review clearly distinguishes protected impact and unverified consumer acceptance. The selector's dated or refreshing pages cannot supply a new actionable release selection.

**Confirm assignment** first retains the minimal original reference, then sends the typed whole-map PUT once with its original strong ETag and key. Native write plus original-result lookup permissions are required independently at the actual binding. A concurrent decision produces a resolved original conflict; the intended map stays in memory while the fresh current map is shown. The operator must deliberately discard/reconcile and review again. Refresh never silently rebases a dirty draft. No automatic retry, replacement key, queued mutation or inverse rollback is inferred.

Original recovery calls the same-key native lookup directly, without application, definitions, editor, source content or map prefetch. Lookup-only access can therefore remain useful after read/write access is removed. Known committed, rejected, conflict and not-committed facts are retained until explicit dismissal; a later unresolved lookup cannot replace them. The shared session/target owner clears affected protected values on permission or session changes, dates permitted outage snapshots, joins actual callbacks and preserves payload-free original references across reload.

Already-issued map/action/selector readers and local read-state application settle before lookup admission; denied and unavailable reads are settled outcomes, not an authorization gate. Recovery starts no prefetch and never requires those reads to succeed. Its stable logical read and exact original targets are installed before admission so delayed same-view initialization does not cancel the lookup. A genuinely changed target/session still cancels while retaining actual callback custody. This ordering is covered with real shared owner/receipt primitives, including a denied read followed by independently authorized lookup.
