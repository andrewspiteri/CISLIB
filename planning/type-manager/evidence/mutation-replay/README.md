# Individual mutation replay diagnostic checkpoint

14 October 2026. Development evidence only; TM-027 and the original 90% mutation
gate remain open. This experiment does not alter native Stryker classifications,
approve equivalent mutants, or qualify the shipping Core/package.

## Executed result

All 238 original compile-error variants were covered exactly once:

| Replay outcome | Variants |
| --- | ---: |
| Persistent C# compiler rejection | 60 |
| Repeated test kill | 95 |
| Survived all 90 cases | 83 |

Thus 178 of the native compile-error variants compile independently. Seventeen
require the explicitly recorded relaxed policy. No timeout, incomplete native run
or unstable repeated outcome occurred. Each batch passed its initial/final 90-case
baseline and nine normalized 90-case controls; strict/relaxed control DLLs matched.
The independent audit reconciles 306 native test runs and 27,540 case executions,
including deliberate failing mutant runs. These are repeated executions of 90
cases, not 27,540 distinct passing tests. Original Stryker results and score stay
unchanged, and no equivalent/unreachable disposition is approved here.

## Why this exists

The strengthened native Stryker 4.16.0 run discovered 483 mutants across the nine
TypeManagement source files. It reported 103 killed, 45 surviving, 40 uncovered,
238 compile errors and 57 native-filter exclusions, with an unchanged failing
score of 54.79%. Safe-mode rollback removed whole methods, so a native compile-error
label alone does not show that each individual mutation fails to compile.

This checkpoint reconstructs every native mutation with the exact installed
Stryker mutators, then replays the 238 compile-error variants individually in three disjoint batches
(80, 79 and 79 variants). Each batch has separate source/output directories, its
own baseline and nine normalized controls, and a final unmutated restoration.
The batches run concurrently; this is correctness evidence, not timing evidence.
The original report stays immutable. Results from this experiment must not be
added directly to Stryker's score or counted as approved exclusions.

## Reconstruction and controls

`ApplyNativeMutation.cs` loads the pinned tool's actual IMutator implementations.
It requires a unique match for the report's source span, mutator display name and
replacement. Roslyn handles UTF-16 positions. It parenthesizes operator/pattern
nodes before serialization and compares the entire reparsed node/token tree.
All 483 variants match uniquely; directives are rejected. This uses an isolated
TypeManagement semantic model, not a complete production Core compilation.

Each of the nine files also has an unmutated normalized control. Controls must
build under strict settings and pass the same 90 native cases. Original and
normalized unmutated Core/test DLLs must each be byte-identical under strict and
relaxed settings before any mutant is interpreted. These are configuration and
serialization controls, not proofs of IL equivalence for arbitrary mutants.

A negative syntax experiment removes the parenthesization rewriter: reconstruction
rejects mutant 4, whose exception-filter pattern otherwise changes structure.
Seven malformed native-report controls reject counter mismatch, duplicate IDs,
aborted summary/counters, missing definitions, unknown outcomes and malformed XML.
The valid 90-case report passes. An explicit CS0168 severity control fails under
an editor-config error override and compiles as a warning under relaxed settings.

## Execution boundaries

`replay-type-manager-mutants.py` checks independent preparation, native-report and
syntax-manifest SHA-256 pins, exact source/test inventories and regenerated bytes.
It rebuilds both Core and tests for each mutation, including possible inlined
constants. Every complete test run has the exact 90 baseline identities, zero
skips, reconciled native counters, and ten observed runtime/Core identities.
Dependency hashes are checked before each test invocation. Kills repeat with the
same failing test names. Partial/invalid native reports are separate outcomes.

Strict build failures are retried with warning escalation, analyzers and editor
configuration disabled. MSBuild item audits require both projects to have no
remaining editor/global analyzer configs, including MSTest's explicit defaults.
Only persistent C# compiler errors receive CompilationRejected. A variant built
only under relaxed settings is explicitly marked strictPolicyRejected. The final
unmutated rebuild must pass 90 tests and reproduce every baseline deployment file.

The supported execution host here is Windows x64, SDK 10.0.401 and .NET 10.0.12.
The target is the isolated TypeManagement source module and six test source files
(71 unit, nine architecture, ten business cases). It is not the actual shipping
CIS.Core binary. Native Ubuntu and final package replay are not claimed.

## Reviews and failed attempts

Read-only Claude reviews led to AST reconstruction, per-file normalization controls,
strict/relaxed binary controls, relaxed configuration audits, rebuilt test assemblies,
complete case/dependency validation and final restoration checks. Payloads contain
Type Manager material only. The final targeted closure verdict is Closed. The first sandbox review could not resolve its API
host; the authorized native retry completed. No review permission was requested.

Retained diagnostic attempts include raw-text and early AST pilots, an incomplete
sandbox baseline, deliberately stopped private replays while review fixes were
added, and the configuration-audit rejection that discovered MSTest's explicit
config. Their original reports remain separate from the final run. No partial run
is promoted to a complete result. The syntax-control failure is retained. Sandbox formatting could not connect to
its build-host pipe; a native formatting/build retry succeeded.

## Reproduction

Start from the mutation-query checkpoint's exact prepared source and unchanged
native report. Copy the canonical helper source into an isolated net10.0 console
project with local empty build targets, pinned SDK/runtime, and references to the
pinned Stryker.Core, Stryker.Abstractions, Stryker.Configuration,
Microsoft.CodeAnalysis and Microsoft.CodeAnalysis.CSharp DLLs. The executed
project/config and helper source are retained with the evidence. Invoke its DLL
with tool directory, prepared Core/TypeManagement directory, native report and an
empty syntax output directory. Inspect/pin the generated manifest independently.

Run the canonical Python replay with --prepared-root,
--expected-preparation-sha256, --native-report, --expected-native-sha256,
--syntax-root, --expected-syntax-sha256 and an empty --output-root. Omitting --ids
selects every native CompileError. The retained `shards.json` supplies explicit
--ids lists for the three executed batches; the aggregate audit requires disjoint
coverage of exactly the native report's 238 CompileError IDs. Commands run from the isolated source directory
containing its pinned global.json. The report is complete only after final baseline
restoration. The retained independent audit reconciles hashes, source variants,
TRX identities, repeated failures and aggregate counts.

Package caches are existing trusted local inputs. This is not a portable toolchain
bundle or clean-cache qualification. Process-level loader scenarios, all surviving
and uncovered variants, native exclusions, build-helper mutations and final six-family
qualification remain separate work.

## Remaining disposition work

Windows-only branch outcomes do not establish Linux equivalence. Surviving
validation, loader, cancellation and diagnostic variants require individual
review and, where they weaken required behavior, stronger executable cases.
Existing runtime process and compatibility suites are not automatically included
in this 90-case source-module mutation harness. No production behavior is changed
by this checkpoint.
