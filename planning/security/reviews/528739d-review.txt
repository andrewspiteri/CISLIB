## Remaining finding

### P2 — A caller joining an existing Entra recheck loses its cancellation request

**Location:** [EntraProfileRuntime.cs, lines 353–355](https://github.com/andrewspiteri/CISLIB/blob/528739d28574aca8bea54a583b5c6e3fc2fba125/implementations/csharp/src/CIS.Security.Entra/EntraProfileRuntime.cs#L353-L355)

The new coalescing path returns the existing recovery task directly:

```csharp
if (recovery is { IsCompleted: false })
{
    return recovery;
}
```

That shared task uses the cancellation token belonging to the caller that started it. A subsequent caller’s token is checked before joining, but never observed again. This conflicts with the public control contract’s requirement that the recheck remains under the caller’s operation ownership. [Public contract](https://github.com/andrewspiteri/CISLIB/blob/528739d28574aca8bea54a583b5c6e3fc2fba125/implementations/csharp/src/CIS.Core/Security/Contracts/ISecurityCredentialControl.cs#L11-L13)

The failure sequence is deterministic:

1. Recheck A starts an SDK acquisition with `CancellationToken.None`; the acquisition remains in flight.
2. Recheck B calls `RequestSourceRecheckAsync(tokenB)` and joins A’s task.
3. `tokenB` is cancelled while that acquisition is still running.
4. The SDK acquisition succeeds, and **B also completes successfully**, despite its cancellation.

The existing concurrency test verifies shared work and disposal settlement, but both recheck calls omit a cancellation token, so it misses this case. [Current test](https://github.com/andrewspiteri/CISLIB/blob/528739d28574aca8bea54a583b5c6e3fc2fba125/implementations/csharp/tests/CIS.Security.IntegrationTests/Entra/EntraWorkloadAcquisitionTests.cs#L316-L377)

**Suggested correction:** retain the single shared acquisition and settlement task, but make a cancellable joining caller observe its own cancellation after the shared work settles successfully. Preserve underlying faults and the existing cleanup guarantees.

A focused regression should hold one recovery acquisition, join with a second caller’s token, cancel only that second caller, then release the SDK successfully. Assert that:

- Only one recovery acquisition occurred.
- The first caller succeeds.
- The second caller observes cancellation.
- The underlying SDK work has actually settled.
