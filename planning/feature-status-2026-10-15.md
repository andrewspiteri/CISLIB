## Repository and package foundation

- Separate CISLIB Git repository, organized for multiple modules and future language implementations under `implementations/<language>`.
- C# uses one `CIS.Core` assembly/package. Public namespaces start with `CIS`, including `CIS.Logging`, `CIS.Logging.MicrosoftLogger` and `CIS.TypeManagement`.
- Explicit version/signing/platform policies, pinned SDK/runtime/toolchain, central dependency versions and lockfiles.
- Two approved Microsoft runtime dependencies. Development tools have separate exact allowlists. Future integrations introducing third-party runtime dependencies, such as NLog, belong in separate packages.
- Shared contracts and conformance cases, native C# tests, compatibility baselines, documentation and verification entry points.
- CIS initialization and graph navigation are present. The latest schema-2 refresh is fresh/valid with 11,509 nodes, 57,761 edges and zero diagnostics (strict=false). Provider runner/test roots and bounded component context are untruncated; the nested test fixture is disambiguated by exact ID. [Build identity and limits](evidence/corrective-provider-compatibility-migration-2026-10-18/README.md). This is navigation evidence, not complete semantic/test coverage or a future graph-freshness guarantee.

| Two-stage bounded queues | A bounded incoming queue precedes encoding/preparation and independent bounded writer queues. Full queues reject new work. A blocked or failed writer does not prevent healthy writers progressing. Queue capacity applies separately to each stage. | [Incoming pipeline](../docs/modules/logging/incoming-pipeline.md), [output queues](../docs/modules/logging/output-queues.md) |

| Files | Exclusive group acquisition, managed inventory, append validation, whole-record size rotation, bounded retention, periodic userspace flush and safe restart/partial-record/transition recovery. | [File startup](../docs/modules/logging/file-startup.md), [rotation](../docs/modules/logging/file-rotation.md), [recovery](../docs/modules/logging/file-recovery-qualification.md) |
| Flush, stop and disposal | Flush captures an incoming prefix and carries it into writer boundaries. One monotonic budget covers preparation, writer work and shutdown cleanup. Stop closes admission; expired preparation is abandoned without late writer dispatch. Actual worker/cleanup Completion remains distinct from the bounded stop result. | [Incoming lifecycle](../docs/modules/logging/incoming-pipeline.md), [flush results](../docs/modules/logging/flush-results.md), [stop/dispose](../docs/modules/logging/stop-dispose.md) |
| Diagnostics and accounting | Immutable incoming and writer observations distinguish processed, failed, abandoned, pending, suppressed and rejected-by-writer work. Processed does not imply delivered. Diagnostic reads do not create completion tasks. Results distinguish completion, success and loss. | [Diagnostics](../docs/modules/logging/diagnostics.md), [delivery observations](../docs/modules/logging/delivery-observations.md), [corrective evidence](evidence/corrective-processing-2026-10-16.md) |
| Microsoft logging provider | ILoggerProvider/ILogger, typed loggers, level/category/EventId/template/state mapping, copied/external scopes, operation correlation, host filtering and nonowning provider disposal. | [Provider qualification](../docs/modules/logging/microsoft-provider-qualification.md), [host qualification](../docs/modules/logging/microsoft-host-qualification.md) |
| Earlier review corrections | Intent-first file retirement, full-group recovery, borrowed invalid-scope handling, explicit-field/EventId precedence, per-output render failures and monotonic deadline observations. | [15 October contract corrections](../docs/modules/logging/review-contract-2026-10-15.md) |

Public incoming acceptance and later per-writer admission are separate observations. Historical partially accepted/per-output-ticket results remain at internal output-stage seams; they do not describe the new public incoming acceptance contract. Later encoding/rendering truncation is observable in the record and subsequent diagnostics rather than by mutating an earlier write result.

These features have executed tests and task-specific evidence. File flush is not a crash-durability guarantee; recovery does not promise exactly-once collector delivery. Collector inspection material does not constitute a shipped collector service.
