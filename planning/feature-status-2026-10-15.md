## Repository and package foundation

- Separate CISLIB Git repository, organized for multiple modules and future language implementations under `implementations/<language>`.
- C# uses one `CIS.Core` assembly/package. Public namespaces start with `CIS`, including `CIS.Logging`, `CIS.Logging.MicrosoftLogger` and `CIS.TypeManagement`.
- Explicit version/signing/platform policies, pinned SDK/runtime/toolchain, central dependency versions and lockfiles.
- Two approved Microsoft runtime dependencies. Development tools have separate exact allowlists. Future integrations introducing third-party runtime dependencies, such as NLog, belong in separate packages.
- Shared contracts and conformance cases, native C# tests, compatibility baselines, documentation and verification entry points.
- CIS initialization and graph navigation are present. The earlier readonly SQLite problem was resolved for the recorded refresh. The last recorded successful graph checkpoint has 10,711 nodes, 51,289 edges and zero diagnostics; this is navigation evidence, not complete semantic or test coverage. Its exact build and scope are retained in the [latest native-migration evidence](evidence/corrective-stop-readers-migration-2026-10-16.md). No live graph-freshness claim is made by this report.

Processed does not imply delivered. Diagnostic reads do not create completion tasks. Public incoming acceptance and later per-writer admission are separate observations. Historical partially accepted/per-output-ticket results remain at internal output-stage seams; they do not describe the new public incoming acceptance contract. Later encoding/rendering truncation is observable in the record and subsequent diagnostics rather than by mutating an earlier write result.

These features have executed tests and task-specific evidence. File flush is not a crash-durability guarantee; recovery does not promise exactly-once collector delivery. Collector inspection material does not constitute a shipped collector service.
