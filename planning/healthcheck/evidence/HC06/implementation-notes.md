# HC06 execution binding implementation notes

Subject: shipping C# source over committed HC02 `c5fd9db6`, authored concurrently with HC03 reporting. HC00 baseline SHA-256 remains `a4e3daaddc0a6cf5d242f2e1acd2f7148644e7b8dd3b65646f7c364a7df9c151`. These notes describe implementation decisions; native execution and candidate qualification belong to the coordinator's separate receipts.

The three public `HealthExecutionBinder.Bind` overloads match the frozen nonshipping facade. They select only Core-owned state access and call the real atomic state binding transaction directly. The factory path never calls public Create first. Suitability, stopping admission, explicit availability publication, identity uniqueness, configuration validation and capacity remain enforced by the single existing state owner. No scheduler, polling loop, Heartbeat replacement, dependency or project is added.

The caller-owned binding serializes accepted fact transactions. It retains only current and previous execution records, one outcome high-water mark, one optional registration event instant, detached bounded diagnostics and the real state target. Execution IDs may have gaps and may reach `Int64.MaxValue`; they are never incremented or wrapped by the binder. Unknown older IDs are obsolete. Retained outcomes are compared before the high-water check; identical repeats are duplicate and contradictions raise a fixed safe `InvalidOperationException`. A first older outcome below the accepted high-water mark cannot replace a newer health observation. Late matching lifecycle and settlement facts may enrich the previous record without moving the current execution backward.

Validation normalizes supplied instants to UTC, compares immutable instants and measured durations, rejects undefined enums and non-finite/negative durations, and enforces the per-kind field matrix. It does not infer elapsed duration or event order from wall-clock timestamps. Secondary steps cannot reopen after a terminal status, and absent/not-invoked phases cannot claim invocation timing. The completion event timestamps required by the matrix are allowed for NotApplicable/NotInvoked completion notifications. Previously absent context can be supplied later; a repeated outcome enriched with context uses the revision 0.4 no-counter state merge, returning Duplicate rather than applying another policy outcome. Diagnostics compare detached values rather than object identity. Integration diagnostics remain lifecycle observations and do not replace an outcome.

Retirement closes binding admission synchronously under the ordering gate, elects one release leader, and performs state withdrawal/cancellation dispatch after leaving that gate. This permits cancellation callbacks to hand off late facts without waiting for the binder lock. The binding retains the actual state settlement Task. One shared asynchronous completion source represents that same real barrier to every DisposeAsync caller, including a caller racing the synchronous release dispatch. It completes only when the actual state barrier completes, and preserves cancellation/failure. An owned monitor withdraws and drains; an external monitor stays caller-owned. The existing collection self-wait detector runs after initiating owned release. BeginStopping prevents new bindings while existing bindings may still finish their final handoffs.

The coordinator owns the revision 0.4 internal state amendment and deletion of the superseded compile-only facade. Independent native tests are owned by the HC06 test agent. This implementation agent did not run builds/tests or mutate Git. Real Heartbeat adapter compilation/activation, external scheduler acceptance and release/platform qualification remain pending because the required Heartbeat runtime does not exist in this repository.
