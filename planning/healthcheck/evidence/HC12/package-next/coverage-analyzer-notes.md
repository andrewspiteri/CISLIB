# Healthcheck native coverage analyzer

The authored development command is `healthcheck-coverage --language-root <path> --package <exact nupkg> --provenance <producer JSON> --reports <native collection directory> --output <new directory>`. Source is under the development-only dependency checker, with independent native artifact rejection controls in `HealthcheckCoverageQualificationTests.cs`. This document records the implementation; actual collection/analyzer results are recorded separately by the coordinator.

The analyzer requires the same package/Core/source producer pins as the package consumer utility. The native collection directory contains `unit/report.trx`, `integration/report.trx` and `business/report.trx`, with each TRX's actual Microsoft Cobertura attachment. `collection.json` pins the selected package, Core asset, collector `Microsoft.CodeCoverage` package `18.10.1`, runsettings and every actual direct/child copy-local Core assembly used by those no-build families. Original files and the complete Core filename inventory are checked again after analysis.

The collector settings include the complete Core module, auto-properties and child processes. Default or explicit source/function/attribute exclusions are rejected. Every family must contain a nonempty, wholly passed native TRX whose actual result rows agree with its counters. Missing/conflicting native attachments fail analysis.

Every native Core report is parsed before Healthcheck is selected. The complete parsed line/branch totals must equal the native top-level totals. Unknown sources, origins outside the selected producer tree, unexpected modules, duplicate class/source/line identities and Healthcheck namespace/path masquerades are rejected. All three families must have the same complete native identity set and branch denominators. Across those fixed identities, line hits combine with OR; covered branch counts combine with MAX as a conservative lower bound. Anonymous branch counts are never summed across families to infer distinct coverage.

Only after those validations does the summary select the exact `src/CIS.Core/Healthcheck/` subtree. Every actual source file is inventoried. Eight reviewed enum/interface-only files are permitted to have no sequence points: the two enum files, public monitor interfaces, execution-binding interfaces, collector interfaces and the three internal state interfaces. Their normalized source hashes are fixed in the analyzer, so a later added implementation body cannot silently inherit declaration-only treatment. All other files require actual native sequence points. This is a declaration inventory, with no executable source exclusions.

The thresholds remain 95% lines and 90% branches. The result includes each file's denominator, uncovered lines, partially covered branch lines and raw native class/source/line gaps. Exit `0` means those thresholds passed; exit `2` retains a valid but unqualified coverage observation; exit `1` means invalid/missing evidence. A coverage gap is not relabeled as a successful gate. The report identifies only the actual platform lane that executed and makes no full-release, mutation, external integration or publication claim.
