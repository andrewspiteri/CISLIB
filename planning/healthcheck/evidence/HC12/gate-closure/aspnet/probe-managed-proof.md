# Narrow managed probe failure attribution

This shared child-proof extension is authored verification code. Native build,
finite real probe execution, derivative parser controls and broad mutation
results remain coordinator-owned and pending for these changed helper inputs.
No historical crash, timeout, compiler status or mutation score is relabelled.

The existing exact HTTP `ArgumentException` registration alternative remains.
A second alternative requires an actual selected/instrumented `CisHealthProbe`
child, exact terminating `NullReferenceException`, first throw frame zero in the
loaded verified Core, unchanged selected controller/ID and Core SHA/MVID, plus
the existing real parent nonzero exit, time, runtime, dependency and stage-owner
checks. Manual source-replay audits still reject every managed failure before
either alternative can apply.

`VerifyProbeNullFrame` reads the actual Core PE metadata. The recorded token must
identify private instance `MoveNext(): void` on a nested type of exactly
`CIS.Healthcheck.Pipes.HealthProbeClient`, implementing framework
`IAsyncStateMachine`. The unique original method must be internal static
`RunAsync(string[], Stream, TextWriter, CancellationToken): Task<int>`, with no
generic method parameters. The actual framework `AsyncStateMachineAttribute`
constructor and serialized type argument must map that method to this exact
nested state-machine type in the same assembly. Names, MVID, method flags,
signatures and metadata token are independently checked. A different Core
method, library/observer frame, exception type, executable or selector fails.
There is no generated-name-prefix heuristic or generic crash allowance.

The observer records the same managed-failure receipt fields after that check;
the auditor repeats the metadata proof and labels successful rows
`managed-core-probe-null`. That child-origin/lifecycle classification supplies
no independent native test or kill credit.

The existing parser-controls command retains its default nine normal-exit
controls. Optional `--managed-probe true` instead requires an actual selected
managed probe receipt already present in the supplied session. It runs three
derivative parser controls: unchanged positive copy; the real Core `RunAsync`
method token substituted for its actual `MoveNext` token; and wrong
`ArgumentException` type on the probe executable. Copies rebind hashes/paths;
the original source receipts, session and staged dependencies remain pinned and
unchanged. This mode creates no process or positive crash receipt and records
`nativeExecution: false` with its own probe-managed control schema. A session
without an actual managed probe receipt is rejected.
