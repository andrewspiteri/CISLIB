# Actual Linux identity boundary qualification

This is authored verification scope, not an execution claim. The coordinator owns CLI wiring, building and actual Linux invocation. The internal entry point is `CIS.Verification.HealthcheckPipeIdentityVerification.RunAsync` with command `healthcheck-pipe-identities --host <packaged fixture DLL> --probe <matching packaged probe DLL> --core-sha256 <actual package Core hash> --output <new directory> [--dotnet <existing pinned Linux dotnet>] [--host-umask 000]`.

The utility refuses execution outside actual Linux and requires actual invoking UID `0`, existing owner `user` UID `1000` and existing nonowner `nobody` UID `65534`, observed through retained `id -u` processes. Existing system `runuser` launches the real supplied fixture and matching probe under those identities. It creates no users, changes no system configuration, and performs no chmod or ownership mutation. The SDK observation is `10.0.401`; actual loaded-origin markers require runtime `10.0.12`, x64 and the supplied Core hash/location. The upstream exact-package receipt establishes the package-to-Core link; this utility validates the supplied consumer files and Core hash directly.

The actual owner fixture runs its production `pipe-live` mode. Its emitted host PID is checked against Linux `/proc/<pid>/status`: real, effective, saved and filesystem UIDs must all be `1000`. Managed `File.GetUnixFileMode` records every mode bit of the actual `CoreFxPipe_` socket path, and retained `stat` verifies actual socket type and owner UID `1000`. Owner read/write bits are required; the verifier does not impose a `0600` socket-mode contract. The pinned runtime checks the accepted peer's effective UID for `CurrentUserOnly`; its Unix socket binding does not set a special restrictive mode. [Pinned .NET 10.0.12 implementation](https://raw.githubusercontent.com/dotnet/runtime/v10.0.12/src/libraries/System.IO.Pipes/src/System/IO/Pipes/NamedPipeServerStream.Unix.cs).

The ordinary lane inherits its process umask and records the resulting mode. A separate optional `--host-umask 000` lane uses the fixed shell command `umask 000; exec "$@"`; the executable and host arguments are passed as positional argv after a fixed shell name, with no command-string interpolation. That lane requires actual managed mode `0777` and matching `stat` output before the nonowner test can qualify identity denial independently of restrictive filesystem permissions. It changes only the newly launched host process's umask, not system configuration or an existing endpoint. Every child shares the same existing temporary directory through process-local `TMPDIR`; no chmod or endpoint ownership mutation occurs.

The positive owner probe must return `0` with a real healthy snapshot. The nonowner probe must load the same exact Core and return `2` through its bounded transport failure path with no snapshot stdout. Server capture counts immediately before and after that attempt must both be `2`, proving no report read occurred. HTTP must remain healthy, and another real owner probe must succeed. The final capture count must be `4`, with no business middleware calls. No root probe is performed, and the result does not claim denial of privileged root or an arbitrary hostile client.

Owned command records preserve exact executable/argv, working directory, PID, timestamps, exit, timeout/forced-termination status and independently hashed stdout/stderr logs. A `runuser` PID denotes that actual owned wrapper; the fixture's own emitted PID is separately retained and verified through `/proc`. HTTP bodies and host process status are retained. Inputs are hashed before and after. The owner sends the real fixture's `exit` command and must observe successful bounded shutdown; any earlier failure terminates and records the owned process tree. Failed attempts remain separate output directories.
