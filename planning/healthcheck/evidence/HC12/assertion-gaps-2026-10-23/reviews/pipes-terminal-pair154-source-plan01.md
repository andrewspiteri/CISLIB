## Concrete obstruction in the literal split

Moving the original Stop/Stop/Start tail into an actual async task and keeping only weak task references outside its construction capsule is insufficient if that tail retains its original finite StopAsync().WaitAsync(Limit) wrappers. In .NET10.0.12, finite WaitAsync constructs a CancellationPromise referencing the actual source Task and a TimerQueueTimer; the timer retains that promise as callback state. The static timer queues retain active timers. Thus a pending timed await can root its async continuation and Server until timer expiry. This is an inference from the exact tagged [Task source](https://raw.githubusercontent.com/dotnet/runtime/v10.0.12/src/libraries/System.Private.CoreLib/src/System/Threading/Tasks/Task.cs) at2582–2678 and [Timer source](https://raw.githubusercontent.com/dotnet/runtime/v10.0.12/src/libraries/System.Private.CoreLib/src/System/Threading/Timer.cs) at44,77–84 and459–473; no runtime collection experiment is claimed. Expiry produces an actual TimeoutException and remains a hold.

The smallest prospective change is to move only deadline supervision outside the terminal-contract task. Inside that task, await the actual uncanceled StopAsync promises directly, in the original sequence; do not insert a timer, cancellation registration, Task.Run, external strong continuation registry or private completion signal. Each stage records an invocation flag immediately before its actual call and a successful-completion flag only after its real await returns. Its scalar/error store contains no Server, clock, timer, Task or delegate. Every escaping task/observer reference is weak. The original StartServer and all real request watchdogs remain; only pending terminal watchdog placement changes. This supervision change requires explicit source approval before implementation.

Outside the no-inline construction capsule, the bounded ownership review retains the existing15s limit and yields while actual owners are alive. Expiry/live graph remains a resource hold; it never sets a success flag or becomes an assertion. Once all real work below has joined and the complete actual resource graph is dead, require the actual first Stop-completion flag first. If it is false, fail that explicit terminal contract assertion immediately. Do not claim the contract task completed, the second Stop ran or Start rejection was exercised. If first Stop completed, require subsequent stage flags in their original order. A collected pending managed promise cycle is evidence of no remaining external owner only within this exact source phase; it is never a successful Stop.

## Terminal failures must keep their causes

Attach real static completion observers and independent error histories to the actual contract Task and cleanup operations. Observers may record success only from real RanToCompletion and must read actual faulted-task exceptions; no continuation may capture Server or the contract Task in its state. A still-live actual observer is genuinely joined after graph release. Invocation alone grants no completion flag. Body/source/clock/callback/state/cleanup errors append unconditionally even when an original assertion also failed.

The literal original post-Stop assertions must retain honest direct assertion behavior when actual Stop and resource cleanup succeeded. Any prospective implementation needs a narrow exact-object path for an original assertion thrown at those literal contract assertion calls, carried separately from unknown runtime errors and released only after all outside resource guards succeed. It must not whitelist every AssertFailedException, suppress an unknown error merely because it equals the primary, or treat an expected terminal Start exception as a general source/factory exception allowance. The Concurrent Start assertion must continue to execute the original actual Start call; unknown errors observed at that call or in resources remain held even if the assertion framework also reports a failure. If precise cause preservation cannot be achieved without widening these boundaries, retain that source limitation and do not adopt the combined candidate.
