This is a finite authored qualification plan for the implementation committed at `0bf0c4c8d8c0c6646f591c634e66cfa480348aa6`. It does not claim execution, mutation kills, coverage or release acceptance. The coordinator records actual native attempts separately. Exact source bytes are restored after every row, every selected project is freshly built before its native run, and both full unmutated Healthcheck baselines are rebuilt and rerun at the end, including after a failure.

Its one positive case and 25 independent compiled-fact controls test the same finite policy against missing/exposed public types, forbidden directions, retained mutable snapshot state and unauthorized mutators. The inspector covers member/signature/attribute/IL references, including generated nested/async types. It does not infer reflection strings or dynamic runtime resolution. These controls validate the detector and are not production mutation kills.

The exact current public Healthcheck type inventory is 54 types in `CIS.Core`, including the single approved ASP.NET extension namespace. The policy/state/collector/binder layer cannot use HTTP, pipe or network infrastructure. Healthcheck types cannot resolve DI, depend on absent Heartbeat/startup implementations, or transfer state/collector ownership to transport helpers. Transport code reads `IHealthSnapshotSource`; it does not construct or retain the service, state coordinator, monitor factory or collector capabilities. The eight snapshot DTO classes remain sealed, getter-only values with private readonly fields and no public constructors. Runtime tests separately establish coherent snapshots, copied collection storage and inert construction. This does not reinstate the superseded assembly-wide ASP.NET ban.

## Follow-on scopes and process boundaries

The finite matrix deliberately extends beyond the first Stryker file: collection freshness and real lease/slot settlement, binder outcome deduplication, bounded complete formatting, strict framing/response interpretation, total monotonic deadlines and probe exit codes. Run every matrix mutation against its named actual native filter, and require a passing baseline plus an assertion failure for that mutant. A compiler/build failure, zero test discovery, launch fault or timeout is not the named kill. Restore the exact pinned source bytes before preparing the next row and freshly rebuild that row's selected project.

The authored finite runner is `HealthcheckCriticalMutationVerification.RunAsync` under `eng/CIS.DependencyChecker/HealthcheckQualification/Mutation/`. It accepts `--repo-root <path> --matrix <path> --output <empty-isolated-path>` and optional `--dotnet <path>`. The coordinator owns its CLI dispatch and actual execution. It retains the input inventory, exact matrix, build/test process logs, changed sources/patch hashes, selected native TRX cases and test/fixture/probe Core DLLs. It validates every source pin/unique anchor before mutation, establishes passing full Healthcheck unit and integration baselines, and requires all 20 selected controls to fail through their native assertions. Its final restoration includes fresh unmutated builds and both full baselines even when an earlier control fails. This runner implements the explicit matrix only; the separately proposed Stryker selection remains a separate qualification attempt.

The `expectedFailures` map binds each control to the actual test assertion, explicit reviewed native source sequence points, printed assertion expression and expected values/Boolean result. Probe controls also restrict the data row: unhealthy/not-ready exit 1 incorrectly observed as 0, or contradictory-ready exit 2 incorrectly observed as 0. An unrelated failed assertion, even in the selected method, is not a kill. Known timeout/protocol/launch diagnostics are rejected. Before integration execution, the runner checks actual child executable DLLs, deps and pinned disabled-roll-forward runtimeconfigs against their fresh project outputs and verifies the Core runtime dependency/copies. Native discovery and result IDs must still match the passing baseline.

Subsequent automatic selections must include the collection-state partial, collector runner, binder/record/validation, formatter/buffer/protocol and transport sources. In-process pipe tests can measure the instrumented Core loaded by their test host. Kestrel fixture and probe tests launch separate applications with copied Core DLLs; their passing tests do not prove those child binaries were mutated. For such rows, the manual isolated mutation build must build the actual host/probe and integration project after the mutation and preserve hashes of every launched `CIS.Core.dll`. Do not grant kill or coverage credit to a child running an unmutated copied DLL.

The current execution binder accepts detached execution facts and the CountryList development example owns startup explicitly. Real Heartbeat scheduling/registration/handler/cleanup/retirement handoffs and an actual generic `IStartable` coordinator remain absent. No mutation row simulates them as completed external integrations. Linux endpoint permissions/identity isolation, exact-package examples/probe, six-family release evidence, supported platform lanes and real published-history replay remain separate requirements. An empty publication ledger cannot establish a historical Healthcheck compatibility pass.
