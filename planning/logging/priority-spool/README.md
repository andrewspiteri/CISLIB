## Integration contract (F0)

- Use each owned event's immutable `TimestampUtc.UtcTicks` as its creation key, including when publication is delayed. Equal timestamps have equal age; a stable slot tie-break is allowed. This selects the timestamp alternative expressly permitted by the user, replacing D05's provisional CreationSequence preference. No age counter, epoch protocol or producer lock is needed. Reindexing never changes age; clock adjustments affect timestamp ordering, not queue safety.
- Keep `IncomingSequence` positive as a correlation ticket. It is not the event age or an admission prefix. Its finite positive range may repeat on rollover; it never causes admission rejection. Frontend flush no longer interprets this value as a cutoff. Output-stage accepted sequence boundaries retain their existing meaning.
- Add startup-captured global/per-level scan percentages and an idle-poll interval to `LoggingOptions`; preserve all existing defaults. Unset overrides inherit the 30% fallback. The initial profile is 20/30/40/50/60/70%. Start measurement with a 1 ms idle interval, separate from file flushing; no idle delay while work remains. Validate before launching workers, including direct configured composition.
- A live incoming snapshot exposes admissions, consumption, actual evictions, abandonment, waiting, active publishers and saturation/inexactness separately from backend Processed/Failed/writer rejection. Independent atomic reads are not a coherent lifetime cut. Saturating counters use a fixed-cost increment with a sticky saturation indication, never a CAS retry loop or admission limit.
- A frontend flush result explicitly carries a nullable captured-batch observation. Before capture completes, it reports NoBatchCaptured rather than zero target counts. A captured batch has exact frozen Consumed/Evicted/Abandoned/Pending counts. Runtime `FlushAsync` additionally waits for the output boundaries registered after that batch's backend dispatch finishes. Its delivery success still requires successful output writes/flushes and no covered frontend loss. It does not claim an instantaneous incoming prefix. Document this narrow membership amendment explicitly in public contracts; do not relabel handoff as processing or writing.
- Preserve existing result properties and enum values; add explicit failure/cancellation states and safe error codes for frontend lifecycle operations. Frontend callback misuse, bad timeout, timer/worker faults and canceled waits produce results instead of recoverable exceptions or faulted/canceled operation tasks. Keep backend-only internal qualification seams separately identified. Add a safe startup-result entry point for public creation without changing the established runtime-returning `Create` signatures; the legacy throwing adapter remains documented. This entry point must perform real composition, not expose a placeholder.
- Startup results remain data-only: `TryCreate(out CoreLogRuntime? runtime)` returns `LogStartResult` with success/error facts and returns the application-owned runtime separately. The repository ownership gate correctly rejected the first result-held runtime; no orchestration reference is allowed in result/diagnostic data and no gate waiver was added.
- Stop snapshots use lifetime frontend accounting plus unresolved publisher/consumer/backend work, not a fictitious single flush batch. Stop shares one operation and deadline; frontend completion requires publisher zero and a final pass. Expiry requests safe cleanup and does not preempt an active backend operation. A timeout observation stays frozen even if cleanup later succeeds.
- Only consumer/control request coordination may lock. Never hold it over a capacity-sized scan, sorting, awaits, backend callbacks or I/O. Ordinary enqueue does not use it. No changes to backend policy order, duplicate semantics, output overflow, recovery or ownership.
