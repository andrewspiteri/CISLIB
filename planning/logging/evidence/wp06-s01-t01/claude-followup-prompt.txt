# Microsoft provider foundation

CoreLoggerProvider lives in CIS.Logging.MicrosoftLogger inside the existing CIS.Core assembly/package. It implements ILoggerProvider and creates private category loggers that call the existing CoreLogger.WriteLazy path. It adds no runtime dependency or logging worker. Constructor runtime and category names are validated; category names use the existing core component rules (1-255 valid Unicode scalars, nonblank, no controls).

The first foundation forwards the supplied rendered message, optional named event (log.message when absent/empty), severity and exception into actual core capture/admission. A controlled Error record verifies the formatter receives the exact exception instance, core captures its type/message, and Exception.Data is excluded. Standard Microsoft LogInformation formatting is exercised without a template parser. The current severity numbers match the pinned Core/Microsoft enums and are validated before conversion. Core handles disabled/filtered/stopped/faulted interest before the lazy formatter and owns output decisions. Caller formatter exceptions retain their original identity. Numeric EventId, template and structured state mapping remain WP06-S01-T02/T03; their absence here is not a final v1 mapping claim. T04/T05 retain complete rejection/filter and story qualification.

Each provider borrows its runtime. Dispose is idempotent, disables future logger calls and rejects further category creation, while direct core logging and another provider remain usable. An already-running call may finish; disposal does not try to interrupt caller formatting. There is no owning-mode constructor, category cache, shared runtime shutdown or retry.

The initial category logger supports OperationContextData in ILogger.BeginScope through the existing runtime-owned bounded scope store. It copies caller input and enforces the core closure guard; caller handles remain creator-owned and follow core LIFO/detection-limit rules. Other Microsoft scope forms currently raise ArgumentException rather than being silently lost. Host/external scope adaptation is WP06-S02-T01/T02. The unpublished final reference surface still proposes ISupportExternalScope/SetScopeProvider and the public runtime BeginScope; those members remain integration work, with no shipping no-op member added for them in T01.

Nine unit cases, eight physical consumer cases and two compiled architecture checks qualify this foundation. Consumer cases use the real public runtime factory, actual file ownership, automatic identity, framework logging extensions and copied typed scopes. The independent native reader validates the child PID/runtime/assemblies, actual file bytes, exact category/event/message observations and twenty-four deliberately corrupted reports. Executed checkpoints and review status belong in the task receipt; this document does not substitute for a run.

The provider's public Microsoft types are isolated under its namespace inside Core. Direct CIS.Logging public types retain their Microsoft-independent signatures. The existing approved Microsoft.Extensions.Logging.Abstractions dependency and complete allowlist stay unchanged. Full provider mapping/external scopes, complete v1 surface, examples, guidance/skills and release remain required.
