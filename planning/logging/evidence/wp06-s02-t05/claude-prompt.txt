# Microsoft host filtering

Core's console and file thresholds are independent. The Microsoft host applies its own provider/category filter before calling `CoreLoggerProvider`. Set that host filter at least as verbose as the most verbose enabled Core destination. A Warning host filter silently removes Debug file diagnostics; Core cannot recover or count events it never receives.

For a file at Debug and console at Warning, configure Core before creating its runtime, then register the provider with a broad provider-specific filter:

```csharp
using CIS;
using CIS.Logging;
using CIS.Logging.MicrosoftLogger;
using Microsoft.Extensions.Logging;

EnvironmentOptions.Logging.ConsoleLevel = CoreLogLevel.Warning;
EnvironmentOptions.Logging.FileLevel = CoreLogLevel.Debug;
EnvironmentOptions.Logging.FilePath = "logs/application.jsonl";
await using CoreLogRuntime runtime = CoreLogRuntime.Create();
using var provider = new CoreLoggerProvider(runtime);
using ILoggerFactory factory = LoggerFactory.Create(builder =>
{
    builder.ClearProviders(); // Standalone example chooses only the Core provider.
    builder.SetMinimumLevel(LogLevel.Warning);
    builder.AddProvider(provider);
    builder.AddFilter<CoreLoggerProvider>(null, LogLevel.Trace);
});
ILogger logger = factory.CreateLogger("Application.Work");
logger.LogDebug("Loaded {Count} items", 7); // File only.
logger.LogWarning("Retrying {Count} items", 7); // File and console.

// Finish application/background logging work before stopping its shared runtime.
LogStopResult result = await runtime.StopAsync(CancellationToken.None);
if (!result.Succeeded || result.LossObserved)
{
    // Application handles the actual drain observation.
}
```

The host application supplies `Microsoft.Extensions.Logging` (or its existing host/framework); `CIS.Core` continues to require only its approved logging abstractions closure. In an existing application, configure its existing `ILoggingBuilder` rather than creating a second factory. Keep its other providers unless intentionally replacing them; `ClearProviders` above is specific to the standalone example.

Trace at the Core provider's host boundary is a simple choice that also permits a future Core Trace destination. If all enabled Core destinations start at Debug, Debug is sufficient. Ignore disabled (`None`) destinations when selecting the most verbose threshold. When every Core destination is disabled, Core skips formatting and state capture even if the host boundary permits Trace. No automatic host-filter rewriting or minimum-level helper is added.

Microsoft selects provider-specific rules before general rules, then the longest matching category prefix, then the last equally specific rule. Consequently `SetMinimumLevel(Trace)` alone cannot override an existing narrower provider/category rule. The provider-wide filter above overrides a general category Warning rule, but a matching `AddFilter<CoreLoggerProvider>("Application.Work", LogLevel.Warning)` still suppresses that category's Debug events. Review effective rules for every category whose diagnostics must reach Core, including configuration loaded by the application. See [Microsoft's filtering rule selection](https://learn.microsoft.com/en-us/dotnet/core/extensions/logging/overview#how-filtering-rules-are-applied).

Core checks destination interest before invoking the supplied formatter or copying structured state. This avoids that callback work for Trace with a Debug file/Warning console. Ordinary argument expressions run before the logging call: guard expensive argument construction with `logger.IsEnabled(level)` or use the application's existing generated logging pattern. Neither the guard nor a successful Core stop proves that host-suppressed events were delivered.

Seven fresh-process cases use the actual Microsoft `LoggerFactory` and real Core public runtime, JSONL console on stderr and physical JSONL file. They cover broad host rules, provider-specific override of a general category rule, a broad provider/category rule, deliberately narrow host and category rules, a Trace file, and all Core outputs disabled. Narrow cases also write Debug directly through Core to prove the destination is interested despite host suppression. Formatter and enumerable traversal counts assert skipped work; exact console/file records and stop counters assert separate delivery. These are filter checks; [host qualification](microsoft-host-qualification.md) binds them to complete asynchronous scope, provider ownership and application shutdown story acceptance. The fixture's four additional Microsoft packages are development-only and separately inventoried. Full release qualification remains pending.

The guidance snippet mirrors the factory configuration exercised by `ProviderHostFilterFixture` in its `broad` case. It is not an independently packaged/activated skill example; candidate-package example verification remains WP08.

# Microsoft provider interest and rejection

ILogger.IsEnabled delegates to Core after validating the level. None, no interested output, closed admission, a disposed provider, and all interested outputs faulted return false. A full queue remains interested: Log still formats and captures once, then Core counts each full output without admitting a ticket. Each healthy interested output admits independently; a faulted output does not prevent another output from accepting the same capture. There is no automatic writer retry or replacement.

Log validates the formatter before the level, even after disposal or shutdown. Before either callback, Core applies closure/interest/fault gates. Filtered calls, including Log(None), update existing output filtered counts; all-faulted interested calls update unavailable counts; stopped and disposed calls perform no capture. Provider disposal disables its loggers and leaves application runtime ownership intact. Concurrent disposal/closure after the first check follows the existing Core capture/admission race contract.

The supplied formatter receives the original state and exception once. Its exception propagates unchanged from the provider's category logger without invalid-event accounting. Microsoft LoggerFactory composition aggregates provider exceptions; [host qualification](microsoft-host-qualification.md) verifies the original formatter exception instance. A null or invalid Unicode message, invalid event name, unsupported retained state, malformed OriginalFormat, or cooperative state enumeration failure counts one Core InvalidEvent and admits nothing to any output. ILogger.Log is void and discards Core's result; applications observe loss through Core diagnostics and flush/stop results. Capture callback failures use the existing fixed UnsupportedValue category; malformed adapted templates currently use this same category because the template is supplied inside capture. No exception text becomes a fault category. Argument guards still throw. Owned encoder consistency failures and catastrophic failures keep their Core behavior.

Oversized valid payloads are truncated under existing node, depth, scalar and entry-byte bounds. They count as truncated rather than invalid. Root metadata scanning continues under the 1024-entry limit after ordinary value copying stops, preserving Microsoft's final OriginalFormat when visited. At the root only, ordinary keys/values beyond the retained budget are omitted without validation. Nested maps still validate the first observed excess key under the existing Core policy. A template beyond the entry scan guard is also omitted with truncation. EventId is ordinary payload under merged scope and byte truncation; aggregate projection can omit it. Duplicate OriginalFormat and nested keys use the last visited value. Supported type/root shape details are in [structured state](microsoft-provider-state.md).

State enumeration is synchronous cooperative caller code. The formatter can itself enumerate a collection before capture; single-use enumerables can therefore fail the second traversal and invalidate the whole event. Materialize them before logging. There is no imposed deadline, arbitrary ToString fallback or reflection serializer.

# Microsoft provider ownership

`CoreLoggerProvider(CoreLogRuntime)` always borrows the application runtime. `Dispose` is idempotent: it disables this provider's future logging calls and releases its borrowed external scope-source reference. It never stops or disposes Core, closes its file output, releases its file-group lease, or disposes a borrowed host scope source. There is no owning constructor option or extra lifecycle service.

The application finishes background work, explicitly calls `runtime.StopAsync`, observes the returned drain result, and disposes the runtime. Another provider over the same runtime and direct Core loggers remain usable after one provider is disposed. `DisposeAsync` joins Core's existing bounded shutdown. [Host qualification](microsoft-host-qualification.md) covers complete application/factory shutdown ordering and concurrent flows; this guide covers direct provider ownership.

A disposed provider returns false from its category loggers' `IsEnabled`; their valid `Log` calls perform no formatter or state capture. `CreateLogger`, `SetScopeProvider` and non-null `BeginScope` throw `ObjectDisposedException`. Existing argument guards still run in their documented order. A call already past the provider's disposal check can finish. Each such call retains the host scope-source reference it captured at entry; disposal does not interrupt its formatter or invalidate that source.

Owned `BeginScope` handles belong to the creating caller. Provider disposal does not pop their Core frames: direct logging observes them until the creator disposes the handles. LIFO checks and repeated valid disposal remain Core's existing rules. Host handles likewise stay with the host and remain active until it disposes them. See [scope capture](microsoft-provider-scopes.md) for layering and .NET child-flow detection limits.

The provider has no category cache, owned host scope source, timer, output worker or stream to close. Its disposed loggers/provider objects can still hold ordinary managed references to the borrowed runtime; the application must release its own references when finished. Clearing the external source reference does not promise a particular garbage-collection schedule. The reference-release test uses a non-inlined registration helper and explicit collections on the pinned managed .NET 10.0.12 qualification lanes; those operations are confined to the test fixture.

Four fresh-process public-runtime cases write actual physical JSONL. They prove direct/second-provider use and lease retention after provider disposal; creator-owned nested scope survival/LIFO cleanup; external source reference release without disposing that source; and a barrier-held formatter finishing with its original host scope after disposal. The application then stops Core, observes exact terminal counters and opens the released lease. [Host qualification](microsoft-host-qualification.md) covers complete factory/application story acceptance; candidate-package examples and release qualification remain pending.

    internal LogWriteResult Write(string component, CoreLogLevel level, LogEventData? data, Func<LogEventData>? factory)
    {

        }

    // Loss counters retain a nonnegative lower bound once Int64 can no longer represent the total.
    private static void IncrementLossCounter(ref long counter)
    {
        long current = Interlocked.Read(ref counter);
        while (current != long.MaxValue)
        {
            long observed = Interlocked.CompareExchange(ref counter, current + 1, current);
            if (observed == current) { return; }
            current = observed;
        }
    }

    {

        foreach (Output output in outputs)
        {
            LogOutputWriteStatus status;
            if (Interested(output, level))
            {
                output.Admission.RecordUnavailable();
                status = LogOutputWriteStatus.Faulted;
            }
            else
            {
                output.Admission.RecordFiltered();
                status = LogOutputWriteStatus.Filtered;
            }
            observations.Add(new LogOutputWriteResult(output.Name, status, null));
        }
        return new LogWriteResult(outcome, observations);
    }

    private LogWriteResult Admit(CoreLogLevel level, EncodedEvent captured, ReadOnlyMemory<byte>? consoleLine, ReadOnlyMemory<byte>? fileLine, bool isTruncated)
    {
        var observations = new List<LogOutputWriteResult>(outputs.Length);
        int accepted = 0;
        int interested = 0;
        foreach (Output output in outputs)
        {
            long? sequence = null;
            LogOutputWriteStatus status;
            if (!Interested(output, level))
            {
                output.Admission.RecordFiltered();
                status = LogOutputWriteStatus.Filtered;
            }
            else
            {
                interested++;
                if (output.Admission.IsFaulted)
                {
                    output.Admission.RecordUnavailable();
                    status = LogOutputWriteStatus.Faulted;
                }
                else if (output.Name == "console" && consoleLine is { } preparedLine)
                { status = queuedOutputs!.Console!.TryAdmit(captured, preparedLine, out sequence); }
                else if (output.Name == "file" && fileLine is { } preparedFileLine)
                { status = queuedOutputs!.File!.TryAdmit(captured, preparedFileLine, out sequence); }
                else { status = output.Admission.TryAdmit(captured, out sequence); }
                if (status == LogOutputWriteStatus.Accepted) { accepted++; }
            }
            if (Interested(output, level) && status is not (LogOutputWriteStatus.Accepted or LogOutputWriteStatus.QueueFull or LogOutputWriteStatus.Faulted))
            {
                throw new InvalidOperationException("Output admission returned an invalid status.");
            }
            if (status == LogOutputWriteStatus.Accepted ? sequence is null or <= 0 : sequence is not null)
            {
                throw new InvalidOperationException("Output admission returned an invalid ticket.");
            }
            observations.Add(new LogOutputWriteResult(output.Name, status, sequence));
        }
        LogWriteOutcome outcome = LogWriteOutcome.Rejected;
        if (accepted == interested) { outcome = LogWriteOutcome.Accepted; }
        else if (accepted > 0) { outcome = LogWriteOutcome.PartiallyAccepted; }
        return new LogWriteResult(outcome, observations, isTruncated: isTruncated);
    }

    private static string CaptureError(string? name, string? message, string? template, string? operationId)
    {
        foreach (string? text in new[] { name, message, template, operationId })
        {
            if (text is not null && !UnicodeScalarText.IsValid(text, int.MaxValue, allowControls: true)) { return "InvalidUnicode"; }
        }
        if (string.IsNullOrEmpty(name) || !UnicodeScalarText.IsValid(name, 255, allowControls: false)) { return "InvalidEventName"; }
        if (message is null) { return "InvalidMessage"; }
        string? operation = operationId?.Trim();
        if (!string.IsNullOrEmpty(operation) && !UnicodeScalarText.IsValid(operation, 255, allowControls: false)) { return "InvalidOperationId"; }
        // Arbitrary cooperative callback/unsupported payload failures expose only this fixed code.
        return "UnsupportedValue";
    }

    private static void ValidateSettings(CoreLogLevel console, CoreLogLevel file, int maximumBytes)
    {

        if (maximumBytes is < LoggingOptions.MinimumMaxEntryBytes or > LoggingOptions.MaximumMaxEntryBytes) { throw new ArgumentOutOfRangeException("options"); }
    }

    {
        if (!Enum.IsDefined(level)) { throw new ArgumentOutOfRangeException(nameof(level), "Use a declared logging level."); }
    }
