# Unpublished Healthcheck initial candidate

`api.json` is an independently curated transcription of HC00 C01–C09, the concrete
surface supplement, the frozen declarations and compiler consumers. Its 54 types
and 309 required members include enum assignments, inheritance, public interface
implementation, CLR types, nullable reference/value types, required/init modifiers,
parameter names and optional argument defaults. Native reflection checks actual
Core declarations. Backward-compatible additions are permitted; removal or a
changed selected signature is rejected. The HTTP extension's compiler-call shape
is also retained by the original HC00 consumer.

`configuration.json` contains 29 independently authored C09 expectations: defaults,
setup/environment precedence, blanks, invariant parsing under a French culture,
inclusive ranges, rejection boundaries, disabled-transport validation and exact
issue keys/codes. Each native case saves, clears and restores all eight module
environment settings. Constructors are separately checked under an invalid
deployment value to prove they use explicitly supplied options.

`baseline-hashes.json` pins these two files. The native test source selects that
manifest hash and the original HC00 receipt hash. It also validates every original
HC00 wire/schema file against the unchanged receipt, before and after execution.
New fixture expectations were authored from contracts, not captured from the
production formatter or resolver.

The actual public service and formatter replay the original deterministic pending
health/readiness and pipe response fixtures. The actual shared internal protocol
reader accepts the independent all-policy/details fixture, including its Int64
decimal string, and rejects the frozen contradictory/version/view/duplicate/frame
inputs. A test-only reflection driver reaches that internal reader without new
friend assemblies; its private spelling is not added to the public API contract.
These are codec boundary checks. The earlier HC09 cases separately exercise real
Kestrel, pipes and CLI processes. Deliberate API/member and observation mismatches
qualify the local comparers; actual malformed payloads qualify reader rejection.

Only JSON object property order is ignored when comparing observations. Scalar
kinds and spelling, decimal strings, omitted members, null, array order and list
contents remain significant. Formatter output is compared with independent frozen
bytes after parsing; no IDs, counters, timestamps, readiness or policy values are
normalized away.

Execution is owned by the integration coordinator through the standard native
compatibility launcher. Authoring is not a pass. These inputs do not create a
published baseline, claim unchanged released consumer execution, or qualify an
exact package, Linux lane, coverage, mutation, real Heartbeat or startup coordinator.
